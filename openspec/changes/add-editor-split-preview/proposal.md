## Why

記事の編集画面のプレビューは、いま**押した回数だけ、画面のいちばん下に現れる**。「表示を確認」を押すと画面全体が送り直され、本文より下に整形された結果が積まれる。見え方を確かめるたびに、書く手を止め、押し、下へスクロールし、また本文まで戻ることになる。

日記は Markdown で書く。段落の切れ目、引用、写真を貼った段落が figure になっているか——**書いている最中に確かめたいものばかりである**。確かめる手数が往復3つあると、確かめないまま書き進め、保存してから直すことになる。

狭い画面ではこれがさらに効く。入力とプレビューが上下に積まれるため、片方を見ているあいだ、もう片方が場所を取り続ける。本文が長くなるほど、プレビューは遠ざかる。**上下に積むのは、狭い画面での並べ方として選ばれたものではなく、広い画面の並べ方がそのまま落ちてきたものである。**

## What Changes

- 記事の編集画面において、本文の入力とプレビューを**同時に見える形**にする。広い画面では左右に並べる。
- プレビューは**入力に追随して更新される**。整形の規則は公開サイトと同じままで、更新のために利用者が操作する必要をなくす。
- 狭い画面では左右に並べず、**入力とプレビューをタブで切り替える**。上下に積むのをやめる。
- プレビューの更新は**保存ではない**。追随して更新されるようになっても、書いた内容がデータストアに入るのは保存を行ったときだけである。この区別が画面の上で曖昧にならないようにする。
- プレビューの更新に失敗しても、**入力中の本文とタイトルは失われない**。更新できなかったことは示すが、そのために編集を止めない。
- 記事の編集画面に限り、広い画面での**紙面の幅を広げる**。いまの幅（40rem）のまま左右に割ると、どちらも読み書きに耐えない。

明示的に含めないもの（非目標）:

- **入力とプレビューのスクロールの同期**。本文の位置とプレビューの位置を対応づけるには、整形の過程で行の対応を持ち回る必要がある。得られるものに対して仕掛けが重い。
- **入力欄そのものの機能追加**。Markdown の色分け、装飾ボタン、WYSIWYG のいずれも行わない。本文は Markdown のまま書き、Markdown のまま保存される（`entry-editing` の既存の判断）。
- **プレビューの結果の保存**。整形した HTML はその場の表示のためだけに使い、データストアには残さない。正はあくまで本文の Markdown である。
- **公開サイトの見た目の変更**。プレビューが公開サイトと同じに見えるのは、既に共有しているスタイルによる。今回そこには触れない。
- **写真の一覧・公開状態・保存の操作の作り直し**。並べ方が変わる範囲で位置は動くが、それぞれの働きは変えない。
- **編集画面以外の画面の幅と配置**。広い紙面はこの画面に限る。

## Capabilities

### New Capabilities

（なし。既存の編集の能力の中で完結する。）

### Modified Capabilities

- `entry-editing`: 「保存の前に公開後の表示を確認できる」を広げる。表示の確認が**本文の入力と同時に見えること**、**入力に追随して更新されること**、そして**画面の広さに応じた並べ方**（広い画面では左右、狭い画面ではタブの切り替え）を足す。あわせて、プレビューの更新が保存を伴わないこと、更新に失敗しても入力を失わないことを足す。整形の規則が公開サイトと同じであることは変えない。

## Impact

- **編集アプリケーション**: `/entries/<日付>` の配置を組み替える。本文の入力とプレビューが1つの領域を分け合う形になり、タイトル・公開状態・保存の操作・写真の一覧はその外に残る。
- **新しい経路**: 本文を受け取って整形結果だけを返す経路を編集アプリケーションに1つ足す。既存の認証の関門（middleware）の内側に置き、未認証の要求には何も返さない。
- **画面のスクリプト**: 入力の変化を拾って更新を要求する処理と、狭い画面でのタブの切り替えを足す。スクリプトが動かない環境では、追随はしないが**確認そのものは従来どおり行える**状態を保つ。
- **レイアウト**: 共有の `Base` が広い紙面を受け取れるようにする。この変更で、プロジェクトに初めて**画面の広さによる分岐**（ブレークポイント）が入る。基準をどこに置くかは design で決める。
- **実行基盤**: 入力のたびに整形の要求が飛ぶため、Lambda の呼び出し回数が増える（間引きは行う）。使っていない時間に費用が発生しない構成は変わらない（`editor-hosting`）。
- **README**: 記事の編集画面の使い方に、左右の並びとタブの切り替えを追記する。
