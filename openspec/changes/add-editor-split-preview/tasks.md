## 1. 整形を返す経路

画面に手を入れる前に、本文を送れば整形結果が返る場所を作る。ここまでは既存の画面の見え方を変えない。

- [x] 1.1 `editor/src/pages/api/preview.ts` を作る。`export const prerender = false`。`POST` のみを受け、body（`text/plain`）を `renderMarkdown()` に通し、`text/html; charset=utf-8` の**断片**を返す（design.md 決定2）
  - `/entries/preview` ではなく `/api/preview` に置く理由（`[date]` の動的経路の隣に「日付ではない `/entries/…`」を作らない）をコメントに残す
  - **DynamoDB に触れない**こと、それによって `entry-editing` の「確認と保存の区別」が触る手段の不在で満たされることを書き残す
  - 本文を `text/plain` で受ける理由（Astro の CSRF 判定が見る content type に含まれ、`allowedDomains` の設定がそのまま効く）を書き残す
- [x] 1.2 `POST` 以外のメソッドに 405 を返す。body が 100KB を超える要求には 413 を返す（決定2）
- [x] 1.3 整形そのものが失敗した場合に 500 と短い本文を返す。**ページを返さない**（受け取る側は断片しか期待していない）
- [x] 1.4 未認証の `POST /api/preview` が 401 になることを確かめる。`editor/src/middleware.ts` の `PUBLIC_PATHS` には**足さない**
- [x] 1.5 `npm run check` を通す

## 2. 編集画面の骨格

`editor/src/pages/entries/[date].astro`。並べ替えと、サーバが描く初期内容まで。スクリプトはまだ足さない。

- [x] 2.1 画面を開いた時点の本文を `renderMarkdown()` に通し、プレビューの面を**描いた状態で**返す（決定3）。保存に失敗してフォームの値で描き直すときも同じ内容を通す
  - 既存の `action=preview` の分岐と初期描画で、整形結果を持つ変数を1つにまとめる
  - この整形が「開いた瞬間から見えている」「スクリプトが動かなくても確認できる」ための前提であることをコメントに残す
- [x] 2.2 プレビューの `<section>` を**フォームの外**へ出し、タイトル・本文・公開状態・操作と同じ grid（`.editor`）の上に並べる。`<form>` に `display: contents` を当てる（決定5）
  - **本文には生の HTML を書ける**ため、整形結果に対話的な要素が現れうること、それが保存のフォームの中にあってはならないことをコメントに残す（写真の一覧をフォームの外に置いている既存の判断と同じ理由）
- [x] 2.3 本文の入力とプレビューを、切り替えの単位となる2つの面にまとめる。タイトル・公開状態・保存の操作・写真の一覧は**面の外**に置き、どちらを見ていても画面に残す（`entry-editing` の「並べ方が変わっても編集の操作は失われない」）
- [x] 2.4 タブ帯のマークアップを足す。`role="tablist"` と、`aria-selected` を持つ `<button type="button">` 2つ（編集／プレビュー）。**既定では `hidden`** にしておき、スクリプトが外す（決定9）
- [x] 2.5 プレビューの面に、状態を出す場所（更新中／最新ではない／ログインが切れた）を作る。何も無いときは空にしておく
- [x] 2.6 「表示を確認」のボタンはマークアップから**消さない**。スクリプトが隠せるよう目印を付ける（決定3）
- [x] 2.7 写真の一覧が従来どおりフォームの外にあり、grid の全幅を占めることを確かめる

## 3. 紙面の幅

- [x] 3.1 `editor/src/layouts/Base.astro` に `wide` の prop を足す。指定された画面でのみ `header` と `main` の幅を `64rem` にする（決定8）
  - 既定は `--page: 40rem` のままであること、広げるのは**明示的に指定した画面だけ**であることをコメントに残す
- [x] 3.2 `[date].astro` から `wide` を渡す。一覧・公開・写真・ログインの各画面は変えない

## 4. 分割とタブの見た目

`[date].astro` の `<style>` に閉じる。**プロジェクト初の幅の分岐**になるので、値をここに置く理由も残す（決定8）。

- [x] 4.1 `.editor` を grid にする。既定（狭い画面）は1列で、タイトル → タブ帯 → 選ばれた面 → 公開状態 → 操作 → 写真の順に縦へ並ぶ
- [x] 4.2 `@media (min-width: 60rem)` で本文の入力とプレビューを2列に並べる。タイトル・公開状態・操作・写真は全幅のまま
- [x] 4.3 分割時、2つの面の高さを `clamp(28rem, 70vh, 46rem)` に揃え、それぞれの中でスクロールさせる。`textarea` の `resize` はこのときだけ止める（決定8）
- [x] 4.4 狭い画面では `.editor` の `data-active` に従って一方だけを見せる。広い画面では `data-active` の値によらず**両方を見せる**（幅の知識を CSS に閉じる。決定9）
- [x] 4.5 タブ帯は狭い画面でだけ見せる。選ばれているタブが見て分かる体裁にする（`entry-editing` の「現在地の判別」）
- [x] 4.6 スクリプトを止めた状態で開き、狭い画面で2つの面が縦に並び、双方に到達できることを確かめる（`entry-editing` の「切り替えが働かない環境」）

## 5. 追随と切り替えのスクリプト

`[date].astro` の `<script>`。**入力欄に書き戻す処理をここに書かない**（`entry-editing` の「表示の更新は編集中の内容を失わせない」）。

- [x] 5.1 起動時に、タブ帯の `hidden` を外し、「表示を確認」のボタンを隠す。`data-active` の既定を `edit` にする（決定3・決定9）
- [x] 5.2 タブの押下で `data-active` と `aria-selected` を切り替える。**面の中身は作り直さない**（`textarea` を作り直すと入力とカーソルの位置が飛ぶ）
- [x] 5.3 `input` を拾い、**400ms** 手が止まったら `POST /api/preview` に本文を送る。直前に整形したものと同じ本文なら送らない（決定4）
- [x] 5.4 要求を同時に1つに保つ。待っているあいだに入力があれば、返ってきたあとで最新の本文をもう1回送る。応答に通し番号を持たせ、**古い応答が新しい表示を上書きしない**ようにする（決定4）
- [x] 5.5 応答を `innerHTML` で差し込む。差し込むのは**サーバが返した断片だけ**で、ブラウザで組み立てた文字列を混ぜない（決定7）
- [x] 5.6 送ってから1秒を超えたら「更新中」を出す。速いときには出さない（決定6）
- [x] 5.7 失敗（ネットワーク・500・413）のとき、**直前の整形結果を残したまま**「最新の内容ではない」ことを出す。次の入力で改めて試みる（決定6）
- [x] 5.8 401 が返ったときは「ログインが切れている」ことを出す。**そのまま保存しても失敗する**状態なので、他の失敗と書き分ける（決定6）
- [x] 5.9 `npm run check` を通し、`npm run format` を当てる

## 6. 手元での確認

AWS の資格が無い環境のため、`npm run dev:editor -- staging` の代わりに次の3つで確かめた。
**staging の実物での確認は 7 群に残っている。**

- ビルド済みのサーバ（`editor/dist/server/entry.mjs`）を、SSM と DynamoDB を手元の偽サーバへ
  向けて起動（`AWS_ENDPOINT_URL`）。middleware も認証もそのまま通る
- ページが実際に埋め込んでいるスクリプトを jsdom の上で動かし、`fetch` を差し替えて
  遅い応答・失敗・401・追い越しを作る
- headless Chrome で 390px / 1280px の見た目を撮る（スクリプト有り・無しの双方）

- [x] 6.1 広い画面で本文の入力とプレビューが左右に並び、書き換えると操作なしで整形結果が追随する（`entry-editing` の「広い画面」「書きながらの確認」）
- [x] 6.2 手を止めたあとのプレビューが、書き換える前の内容を残していない（「入力を止めたあと」）
- [x] 6.3 狭い画面（開発者ツールの端末表示）でタブが出て、上下に積まれない。切り替えても入力していたタイトルと本文が残る（「狭い画面」「切り替えたあとの本文」）
- [x] 6.4 狭い画面でプレビューを見ている状態から、保存・公開状態・写真の一覧に到達できる（「表示を見ている状態での保存」）
- [x] 6.5 スクリプトを止めた状態で、開いた時点の整形結果が見え、「表示を確認」と保存が従来どおり働く（「追随が働かない環境」）
- [x] 6.6 プレビューを何度更新しても保存されない。更新だけを行って画面を閉じ、開き直すと保存済みの内容が出る（「確認と保存の区別」）
- [x] 6.7 経路を落とした状態（開発者ツールでオフライン）で書き続けられ、入力が消えず、最新でないことが出る。回復後の入力で表示が最新に戻る（「更新の失敗」「失敗からの復帰」）
- [x] 6.8 保存の失敗時に入力が残る既存の挙動を壊していない（`entry-editing` の「保存が失敗する」）
- [x] 6.9 「保存して写真を追加」と写真の一覧が従来どおり働く。一覧を見ても入力が消えない
- [x] 6.10 本文に生の `<button>` を書いて保存し、整形結果に現れたそれを押しても**保存のフォームが送信されない**ことを確かめる（決定5 の根拠の確認）
