## Why

ブラウザから日記を書けるようになり、公開も押すだけで済むようになった。**写真だけが手元に残っている。** 写真を1枚入れるには手元の端末に画像を持ってきて `npm run photo -- <環境> --file ... --date ...` を実行し、出力された URL を編集アプリケーションに貼るしかない。

日記に載せる写真は、多くがその日に撮ったものである。撮った端末はたいていブラウザを持っており、そこから日記も書ける。にもかかわらず「写真を入れるためだけに手元の環境へ戻る」が残っていて、外出先で書いた記事は文章だけのまま置かれる。

書く手段と公開する手段をブラウザに広げた以上、写真を入れる手段も同じところに置く。手元の CLI からの投入は、これまでどおり残す。

## What Changes

- 編集アプリケーションに**写真を投入する画面**を置く。日付を選んでファイルを選ぶと元写真が投入され、配信される4つのサイズの URL と、本文にそのまま貼れる Markdown が示される。
- 元写真は**編集アプリケーションを経由せず、ブラウザからアップロード先へ直接送られる**。編集アプリケーションが発行するのは、投入先を1つの日付に限り、短い期間だけ有効な一時的な資格である。写真の大きさが実行基盤の受け取れる要求の上限に縛られない。
- 投入先のキーは**編集アプリケーションが決める**。利用者が任意のキーを指定する経路を作らない。CLI が `--date` に対して作るキーと同じ規則（`YYYY/MM/DD/<ファイル名>`）にし、どちらから投入しても同じ場所に置かれる。
- **派生画像の生成が終わったかどうかを画面で示す。** 生成は非同期であり、投入の直後は URL を開いても画像が返らない。貼ってよい状態になったことが分かるまで待てるようにする。
- 編集アプリケーションの権限に、**自環境のアップロード先への書き込み**と、**自環境の派生画像の生成状況の読み取り**を足す。**配信先への書き込みと写真配信の CDN への権限は引き続き与えない**。公開されるものが元写真から機械的に作られたものに限られる、という現状の担保は変えない。
- 編集の途中から写真の投入へ進んでも、**書きかけの本文を失わない**経路にする。

明示的に含めないもの（非目標）:

- **本文への自動挿入**。どこに何枚入れるかは書き手が決める。画面が示すのは貼れる形までとする。
- **投入済みの写真の一覧・削除**。日記のエントリに削除の操作を持たないのと同じ理由で、元写真を消す経路を作らない。何を入れたかは本文が持つ。
- **複数枚の同時投入**。1枚ずつで足りる。まとめて投入したいときは手元の CLI がある。
- **編集アプリケーションでの縮小・切り抜き・向きの補正**。変換はすべて既存の Lambda が持つ。ブラウザ側は元写真をそのまま送る。

## Capabilities

### New Capabilities

なし。既存の投入経路（`photo-ingest`）に2つ目の入口を足すものであり、新しい能力を導入しない。

### Modified Capabilities

- `photo-ingest`: 投入の入口が手元の CLI に限られない形に広げる。ブラウザから投入する経路、その経路で使う一時的な資格の限定（対象・期間）、投入先のキーを利用者が決められないこと、生成が終わったことを投入した側が知れることを足す。
- `editor-hosting`: 「実行基盤の権限は自環境の日記データと公開手続きの起動に限られる」を書き換える。自環境のアップロード先への書き込みと、派生画像の生成状況の読み取りを認める。**配信先ストレージへの書き込みと写真配信の CDN への権限は引き続き禁じる**。
- `entry-editing`: 書きかけのエントリから写真の投入へ進んでも入力が失われないこと、および投入された写真を本文に貼れる形で得られることを足す。

## Impact

- **編集アプリケーション**: 写真の投入の画面と、投入後に結果を示す経路を追加。presigned POST の生成に AWS SDK の依存を1つ加える。エントリの編集画面に投入への入口を置く。
- **Terraform**: 編集アプリケーションの IAM ポリシーに、自環境のアップロード先への `PutObject` と、配信先に対する存在確認のための読み取りを足す。編集アプリケーションの module がバケットを知る必要があるため、root module からの受け渡しを増やす。**写真の module 側は変更しない**。
- **設定**: `editor/function.jsonnet` と `scripts/dev-editor.sh` に、アップロード先・配信先・配信 URL の3つを足す。いずれも既存の output と環境名から決まるため、`config/<環境>.env` への転記は増えない。
- **共有コード**: URL の組み立て（`src/lib/photo.ts`）とキーの規則は既存のものをそのまま使う。CLI と編集アプリケーションで規約が二重に存在しないようにする。
- **README**: 写真を入れる手順に、ブラウザからの経路を追記する。
