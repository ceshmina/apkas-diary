## 1. 写真を拾う規則

一覧に並べる写真は、日別ページと同じ整形を通した HTML の `img` から拾う（design.md 決定1）。URL は配信パスとサイズ名から組み立てる（決定2）。

- [ ] 1.1 `src/lib/markdown.ts` に、整形した HTML から `img` の `src` を現れる順に返す関数を足す
  - 既存の `RAW_IMG` / `RAW_SRC` を使う。二重引用符・一重引用符・引用符なしのいずれの `src` も読む
  - 属性値の `&amp;` は `&` に戻す（`withEquipmentInRaw` と同じ扱い）
  - **本文の Markdown の文字列から拾わない理由**（`!` の抜けた `[](…)` は画像にならない。design.md Context 4）をコメントに残す
- [ ] 1.2 `src/lib/photo.ts` に、配信パスとサイズ名から配信 URL を組み立てる関数を足す
  - `photoUrlOf(base, size, sourceKey)` を、この関数に `photoPathOf(sourceKey)` を渡す形に書き直す。**作る文字列は変わらない**ことを、空白を含むファイル名を含めて確かめる
  - URL の `/medium/` を置き換える形を採らない理由をコメントに残す
- [ ] 1.3 `src/lib/site-data.ts` に、エントリから一覧に並べる `thumbnail` の URL の列を返す関数を足す
  - 整形は機材の引き当てを渡さずに行う（`renderMarkdown(body)`）
  - 配信パスを取り出せない `src`（外部のサイトの画像など）は落とし、配信パスで重複を除く。順序は HTML に現れる順
  - **エントリの日付ごとに1度だけ整形する memo** を置く。4つの一覧が同じエントリを載せても、整形は1件につき1度
  - 下書きが通らないこと（入力は `publishedEntries()` の結果だけであること）をファイル冒頭のコメントに書き足す
- [ ] 1.4 production の本文で、拾った結果を確かめる
  - 2026-01-25（`[](…)`）は写真を拾わない
  - 2024-03-04 は 35 枚を本文の順に拾う
  - 旧サイトから引き継いだ `table` の中の生の `<img>` も拾う
  - 外部のサイトの画像は拾わない
  - 1,139 件の合計が、日別ページに出ている日記の写真の数と一致する

## 2. 一覧の部品の土台（`src/components/EntryList.astro`）

- [ ] 2.1 行の `<a>` に、題のない行・写真のある行の印（class）を持たせる（design.md 決定4）
  - `.date-block:only-child` による見分けをやめ、印で書き直す。題のない行の添え書きを数字の高さの真ん中に置く、という既存の振る舞いは変えない
  - **写真のない行の姿が、決定7のほかは変わらないこと**を確かめる。変更前後でビルドした一覧の、写真のない行の HTML の差が印の class だけであること、スマートフォン幅では見た目が変わらないこと
- [ ] 2.2 行の `<a>` の中に、縮小画像の並びを置く（design.md 決定3・5）
  - 並びは `aria-hidden="true"` の要素で包み、`img` は `alt=""`・`loading="lazy"`・`decoding="async"`・`width` / `height` を持つ
  - 縮小画像ごとのリンクや `tabindex` は持たせない
  - 写真のない行には、並びの要素そのものを出さない
- [ ] 2.3 縮小画像の共通の体裁を当てる（design.md 決定5）
  - 角は `--radius`、読み込みを待つあいだの面は `--border`。基準にない色や角丸を足さない
  - 縮小画像そのものにはホバーの手応えを付けない。行に触れたときの手応えがそのまま出る
- [ ] 2.4 一覧の日付を、どの一覧でも年つきにする（design.md 決定8）
  - `EntryList.astro` の `showYear` を外し、`src/pages/[year]/index.astro` と `src/pages/[year]/[month]/index.astro` が `showYear={false}` を渡すのをやめる
  - `DateBlock.astro` の `showYear` を外す（使っていたのは一覧だけ）。日別ページの日付が変わらないことを確かめる
  - `src/lib/date.ts` の `datePartsEn` の説明から「年の中の一覧では年を省く」を消す。`{ year: false }` は `formatDateEn` が使っているので残す
  - 年別・月別の一覧で、行の日付が `Sep 2026` と出ること、読み上げの和文が変わらないことを確かめる
- [ ] 2.5 PC 幅の列の幅と間隔を詰める（design.md 決定7）
  - 数字の列は 2.35rem（左寄せのまま）、列の間隔は 1rem
  - 添え書きの列は 4rem（どの一覧も年を含むので1つの幅）
  - 列の幅を字幅から決めたこと（「20」36.9px、「May 2026」61.8px）をコメントに残す
  - 添え書きに `white-space: nowrap` を当てる
  - 実際の書体で、字面のいちばん広い組み合わせ（「20」「May 2026」）が列に収まること、数字が一覧の左端に揃っていることを確かめる
- [ ] 2.6 ページの見出しを本文と同じ字面にする（design.md 決定9、`src/components/PageHead.astro`）
  - 和文の見出し（`h1`）の大きさを `--text-prose`、太さを 400、字間を 0.04em にする。色（`--fg-muted`）と、約物を詰めない指定は残す
  - 部品の冒頭のコメント（「小さなラベルの字面で組む」「字間を広く取るので約物の詰めを外す」）を、本文の字面で組む理由に書き直す
  - トップ・年別・月別・月日ページ・404 の見出しが、飾りの大きな語と字の並びの線（baseline）で揃ったままであることを確かめる
  - トップの「年別」（`.section-title`）と編集アプリケーションの節の題が変わっていないことを確かめる
- [ ] 2.7 部品の冒頭のコメントに、縮小画像を行のリンクの中に置く理由、支援技術から外す理由、写真の説明（`alt`）を一覧で読ませない理由を書く

## 3. 置き方（案 A′ 題の下に並べ、入りきらない日は白に溶かす）

design.md 決定6。見本（https://claude.ai/artifact/84EXkG9ECFwMhiSHTRJ878 の A′）と同じ組みにする。

- [ ] 3.1 スマートフォン幅: 題のある行は題の下に3段目として、題のない行は題の位置に並べる
  - 題のない行の添え書きは、縮小画像のある行では1段目に置く（数字の高さの真ん中に置くのは、縮小画像のない行だけ）
- [ ] 3.2 PC 幅（`min-width: 42.5rem`）: 題のある行は題の列の下に、題のない行は題の列に並べる
- [ ] 3.3 縮小画像を正方形にし、大きさを列の幅から決める
  - `grid-auto-flow: column` と `grid-auto-columns: calc((100% - N * <間隔>) / (N + 0.5))`。並びは `overflow: hidden`
  - N は画面の幅で段を変える: 〜27rem（432px）で 5、〜34.5rem（552px）で 7、〜42.5rem（680px）で 9、PC 幅で 8。N をカスタムプロパティに置き、段ごとにそれだけを替える
  - **半端な「N 枚と半分」にする理由**（入りきるかどうかを段の中では枚数だけで決め、CSS だけで見分けるため）と、**段を変える理由**（大きさを 36〜58px ほどに保つため。N を固定すると 680px 手前で約 100px になる）をコメントに残す
- [ ] 3.4 HTML に載せるのは1行10枚まで（いちばん多く見える段の 9.5 枚ぶん）。「+N」は置かない
- [ ] 3.5 入りきらない行だけ、並びの右端を地の白に溶かす
  - 段ごとに N+1 枚目があるとき（`:has(> img:nth-child(6))`・`(8)`・`(10)`、PC 幅では `(9)`）だけ `mask-image` の gradient を当て、段が上がるたびに下の段での当て方を打ち消す
  - 溶かす幅は、最後の1枚の大きさから決める（見本では 1.15 枚ぶん）
  - 入りきる行（その段で N 枚まで）に溶かしが当たらないこと
  - `:has()` を解さないブラウザでは溶かしが当たらず、半分の1枚が切れて見えるだけで、並びが崩れないこと
- [ ] 3.6 見本と同じエントリ（最近の日記、2024年3月）で見比べ、位置・大きさ・間隔・溶かし方が一致することを確かめる
