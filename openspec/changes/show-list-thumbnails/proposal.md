## Why

エントリの一覧（トップ・年別・月別・過去の同じ日）は、日付と題だけで組まれている。**日記の過半は題を持たない**（公開済み 1,139 件のうち題のあるものは 444 件）。題のない行は日付しか語らないので、一覧を眺めても、どの日に何があったのかを思い出す手がかりがない。

一方で、**写真のある日は全体の約 65%（740 件）ある**。写真は本文に既に貼られており、その縮小画像（`thumbnail`、長辺 240px）も、投入の時点ですべての写真について作られている（`photo-ingest`）。旧サイトから移した写真も含め、作られたまま、まだどこからも使われていない。

写真は題よりも速く「その日」を思い出させる。日記に手を入れずに、既に手元にあるものを並べるだけで、一覧が「日付の索引」から「日々を見渡す場所」に変わる。

## What Changes

- **エントリの一覧の行に、そのエントリの本文に現れる写真の縮小画像を並べる。** 対象はトップ・年別・月別・過去の同じ日の4つで、いずれも同じ一覧の部品（`EntryList`）を通る。
- **並べるのは本文に貼られた、日記自身の写真だけとし、本文に現れる順に並べる。** 外のサイトの画像は並べない。
- **縮小画像は行のリンクの一部とする。** 押すとその日の日別ページへ移る。拡大表示のような、押したときの特別な動作は持たない。
- **写真のない日は、行の姿を変えない。** 空の枠、「写真なし」の類の文言、写真の位置の空白のいずれによっても、写真の不在を欠落として示さない。題・場所の不在と同じ扱いとする。
- **画像は `thumbnail` の派生画像を使う。** 本文の URL のサイズ名を差し替えて得る（`photo-delivery`「サイズ名を差し替えれば同じ写真の別のサイズが得られる」）。目録は引かず、ビルドの問い合わせは増えない。
- **縮小画像は正方形に切り抜き、題の下に並べる。題のない行では題の位置に並べる。** 題のない行が日付しか語らない、という上の問題に最も直接に応える置き方である。
- **枚数では切らない。行に入りきらない日は、並びの右端を地の白に溶かして切る。** 「+N」のような数の表示は置かない。入りきる日には溶かしを当てず、続きがあるように見せない。
- **PC 幅の一覧で、日付の数字・月と曜日・題の間を詰める。** いまは月と曜日の列が字面の倍ほどの幅を持ち、縮小画像を並べると、その空きが題と縮小画像を右へ押しやって目立つ。行どうしの題の位置を揃えるため、写真の有無によらずすべての行に当てる。スマートフォン幅は変えない。
- **一覧の日付の表記を、どの一覧でも年を含む形（`Sep 2026`）に揃える。** いまは年別・月別の一覧だけ年を省いている（`Sep`）。一覧の見え方をそろえ直すのに合わせて、4つの一覧の行を同じ形にする。
- **ページの見出し（「2024年3月の日記」「最近の日記」など）を、本文と同じ字面にする。** いまは字間を大きく広げた小さなラベルの字面で組んでいる。大きさ・太さ・字間を本文にそろえ、色は淡い文字のまま残す。
- 置き方は、実データで組んだ見本（https://claude.ai/artifact/84EXkG9ECFwMhiSHTRJ878）で比べて選んだ（案 A′）。採らなかった案は design.md 決定6 に記す。

### スコープ外

- **日別ページの前後の導線（← Newer / Older →）への縮小画像。** 導線は隣へ移るための手がかりで、一覧とは役割が違う。一覧で見え方が定まってから、必要なら別に決める。
- **縮小画像の拡大、押したときの特別な動作。** 写真と向き合う場所は日別ページの拡大表示であり、一覧はそこへ辿るための場所である。
- **写真だけを並べたページ（ギャラリー）。** 日記の見せ方を1つ増やす話で、一覧に縮小画像を添えることとは別に決められる。
- **本文に貼られていない写真。** 目録には、投入されたが本文に使われていない写真もありうる。一覧に並べるのは読み手が日別ページで出会う写真に限る。
- **編集アプリケーションのエントリ一覧。** 書き手のための一覧で、読み手の一覧とは求めるものが違う。
- **新しい派生サイズの追加。** 既存の4つ（`thumbnail` / `small` / `medium` / `large`）で賄う。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `diary-site-pages`: エントリの一覧に、本文に現れる写真の縮小画像を並べることを要求として加える。写真のない日の扱い、押したときの振る舞い、読み上げ、読み込みの負担、スクリプトに依存しないことを含む。あわせて、一覧の日付をどの一覧でも年を含む同じ書式で示すことを加える。

## Impact

**アプリケーション**

- `src/components/EntryList.astro`: 行に縮小画像を並べる。いま題の有無を `:only-child` で見分けている箇所は、行に縮小画像が加わると成り立たなくなるので、行の側に印を持たせる形に改める。PC 幅の列の幅と間隔を詰める。一覧ごとに年を省く指定（`showYear`）をやめる。
- `src/components/PageHead.astro`: 和文の見出し（`h1`）の大きさ・太さ・字間を本文と同じにする。使っているのはトップ・年別・月別・月日ページと 404 の5つで、いずれも同じ見出しの部品を通る。
- `src/components/DateBlock.astro`: 年を省く指定（`showYear`）は一覧のためだけにあったので外す。日別ページは年つきのまま変わらない。
- `src/lib/date.ts`: `datePartsEn` の説明から「年の中の一覧では年を省く」を外す。`{ year: false }` そのものは前後の導線の日付（`formatDateEn`）が使っているので残す。
- `src/lib/photo.ts`: 配信パスとサイズ名から配信 URL を組み立てる関数を足す。本文の URL から取り出した配信パスを `thumbnail` の URL にするために使う。いまは配信パスを取り出す（`photoPathFromUrl`）までしかない。
- `src/lib/markdown.ts`・`src/lib/site-data.ts`: 日別ページと同じ整形を通した本文の `img` から、日記自身の写真を本文に現れる順に、重複を除いて取り出す。本文の文字列から URL を拾う規則（`PHOTO_URL_PATTERN`）は使わない。画面に出ていない写真まで拾うためである（design.md 決定1）。整形はエントリごとに1度だけ行う。
- 一覧を持つ4つのページ（`src/pages/index.astro`、`src/pages/[year]/index.astro`、`src/pages/[year]/[month]/index.astro`、`src/pages/on-this-day/[monthday].astro`）: 渡すエントリは既に本文を持っているので、写真のための変更は要らない。年別・月別の2つは `showYear={false}` を渡すのをやめる。

**配信物**

- 一覧ページの HTML に `img` が増える。1行に載せるのは10枚まで。いちばん重いのは写真の多い年の年別ページで、2024 年（329 件、写真のある日 300 件）では最大 1,056 枚・約 8MB になる。遅延読み込みにするので、実際に読まれるのは画面に近づいた分である。

**ビルド・基盤・データ**

- 変更なし。目録もエントリも読み方は変わらず、問い合わせも権限も増えない。派生画像は既にすべての写真について揃っている。
