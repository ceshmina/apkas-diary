## Why

この日記の基盤は動いているが、中身がほとんど入っていない。実際の日記は旧サイト（`apkas/eskarun`）の Markdown ファイルとして 2023-01-01 から 2026-06-07 までの **1089件**が存在し、そちらが読まれ続けている。基盤を作った目的はこの日記を長く保つことなので、データが旧サイトに残ったままでは目的を達していない。

移行そのものは日付・タイトル・本文を読み替えるだけで、難しいところはない。問題は**本文の書かれ方**にある。旧サイトの記事には、Markdown では表せない配置のために HTML が直接書かれている。

```
<table>
  <tr>
    <td><img class="caption" src="…20240929-103422.webp" /></td>
    <td><img class="caption" src="…20240929-103520.webp" /></td>
    <td><img class="caption" src="…20240929-103534.webp" /></td>
  </tr>
  <tr>
    <td colspan="3">猫がいた</td>
  </tr>
</table>
```

用途は「画像を横2〜3枚並べ、その並びに説明を添える」の一つだけで、使われているタグも `table` / `tr` / `td` / `img` の4種しかない（86件の記事に188箇所）。旧サイトはこれを CSS で画像グリッドとして見せていたが、この日記には対応するスタイルがない。素の `table` として出るため、列幅が揃わず、説明の行は本文と同じ体裁のただの一文になる。

同じ性質の欠けがあと2つある。

- `![会場](…)` の `[]` に書かれた説明が**画面に出ない**。旧サイトは画像の下にキャプションとして表示していた。97件の記事が該当し、書いた文が読めない状態になる。
- **663件はタイトルを持たない**。日記は毎日書くもので、名前を付けない日のほうが多い。いまの日別ページはタイトルが空だと `(無題)` と出すので、過半のページに欠落を示す文言が並ぶ。

staging に代表16件（検出した全32パターンを網羅する最小の集合）を投入して確認した結果が上記である。横スクロールは起きておらず、壊れているのは体裁と情報の欠けに限られる。

この change では**移せる状態を作るところまで**を行う。取り込みの手段を用意し、表示の欠けを塞ぎ、代表16件で確かめる。1089件を実際にどこへ入れるかは、表示が仕上がってから決める。

## What Changes

- 旧サイトの記事を DynamoDB に取り込む。取り込み用の CLI（`npm run import-legacy`）を追加する。移行のための一時的なコマンドであり、移行後に削除する。
- **タイトルを持たないエントリは、日付そのものを見出しにする**。`(無題)` は出さない。書式は日付行と同じ曜日つき（`2026年1月1日（木）`）で揃え、日付を見出しに出す場合は見出しの上の日付行を出さない。同じ日付が1ページに2度現れることはない。
- **`![説明](…)` の説明を画像の下にキャプションとして表示する**。画像が段落に単独で置かれている場合に `figure` / `figcaption` へ組み替える。文章の途中に置かれた画像は組み替えない。
- **本文中に直接書かれた `table` を画像グリッドとして整える**。列幅を等分し、セルの間隔を与え、行全体に及ぶセル（`td[colspan]`）を並びに対する説明として表示する。

### スコープ外

- **本文の書き換え**。HTML を Markdown に直す、`class` を外すといった加工は行わない。本文は書かれたまま保持し、見せ方は表示側で解く（design.md の決定1）。
- **`img` の `class`（`top` / `middle` / `bottom` / `caption` / `bottom-caption` / `nopb`）の再現**。旧サイトで連続するグリッドを一塊に見せるための余白指定だが、表示が本文中の class 名に依存する状態を続けたくない。グリッド間の余白は一律にする。
- **`location`**。旧サイトの frontmatter にある滞在地（107件）は取り込まない。この日記は場所を扱わない。元のファイルは残るので、扱いたくなったときに読み直せる。
- **数式**。`$2^A$` のような記述が1件だけあるが、そのために数式の処理系を入れる利点がない。文字のまま出る。
- **旧サイトの写真の移設**。画像はすべて `photos.old.apkas.net` にあり、生存を確認済み。参照したまま変えない。
- **全件の取り込み**。staging に入れるのは代表16件までとする。1089件をどこへ入れるか（production への直接の取り込みを含む）は、表示が仕上がったうえで別途決める。

## Capabilities

### New Capabilities

なし。移行は一度きりの操作であり、システムが備え続ける能力ではない。

### Modified Capabilities

- `diary-site-pages`: 日別ページの見出しについて、タイトルを持たないエントリの扱いを要件に加える。あわせて本文の表示について、画像に添えられた説明が読めること、Markdown では表せない配置のために本文中に直接書かれた HTML が読める形で整形されることを要件に加える。いずれも移行するデータで初めて現れる性質であり、いまの要件は「Markdown として整形して表示する」までしか述べていない。

## Impact

**アプリケーション**

- `src/legacy/source.ts`（新規）: 旧サイトの記事ファイルの読み取りと解析。移行後に削除する。
- `src/cli/import-legacy.ts`・`scripts/import-legacy.sh`（新規）: 取り込み CLI。移行後に削除する。
- `src/lib/markdown.ts`: 画像を `figure` / `figcaption` へ組み替える hast プラグインを processor に渡す。
- `src/pages/[year]/[month]/[day].astro`: タイトルのないエントリの見出し、画像グリッドと `figcaption` のスタイル。
- `src/components/EntryList.astro`: 一覧でもタイトルのないエントリを日付だけで示す。日別ページと扱いを揃えるため。

日付の整形（`src/lib/date.ts` の `formatDateJa`）は変えない。見出しと日付行で同じ書式を使う。

書き込み経路（`src/lib/store/put.ts`）は変えない。移行したエントリの `createdAt` は取り込みを実行した時刻になる。

**データ**

- staging の DynamoDB に代表16件が入る（投入済み）。既存のテスト用エントリ6件とは日付が重ならないため、下書きの 2025-12-24 を含めていずれも残る。

**配信物**

- 日別ページのマークアップが変わる（見出し、`figure`、グリッドのスタイル）。この change の範囲では staging のみ。
