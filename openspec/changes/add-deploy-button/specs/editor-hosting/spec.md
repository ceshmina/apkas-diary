## ADDED Requirements

### Requirement: 実行基盤の権限は自環境の日記データと公開手続きの起動に限られる

編集アプリケーションの実行に与える権限は、次の3つに限らなければならない（MUST）。

- 自環境の日記データストアへの読み書き
- 自らの動作に必要な設定値の読み取り
- **自環境の公開手続きを起動すること、およびその実行状況を読み取ること**

他方の環境のリソースへの権限を与えてはならない（MUST NOT）。写真の配信にかかわるリソース、および公開サイトの配信元ストレージと CDN への権限を与えてはならない（MUST NOT）。

公開手続きを起動する権限は、配信物を書き換える権限ではない。編集アプリケーションが起こせるのは「定められた手順を、定められた入力で始めること」だけであり、何をどこへ書くかは手順の側が持つ。編集アプリケーションのコードが乗っ取られても、配信物へ任意の内容を書き込む経路にはならない。

起動できる対象は自環境の公開手続き1つに限定されなければならない（MUST）。

#### Scenario: 他環境への到達

- **WHEN** ある環境の編集アプリケーションが他方の環境のデータストアへアクセスを試みる
- **THEN** 権限がなく拒否される

#### Scenario: 配信物への直接の到達

- **WHEN** 編集アプリケーションが公開サイトまたは写真の配信元へ書き込みを試みる
- **THEN** 権限がなく拒否される

#### Scenario: 公開手続きの起動

- **WHEN** 編集アプリケーションが自環境の公開手続きを起動する
- **THEN** 実行が始まり、その状況を読み取れる

#### Scenario: 他環境の公開手続きの起動

- **WHEN** ある環境の編集アプリケーションが他方の環境の公開手続きの起動を試みる
- **THEN** 権限がなく拒否される

## REMOVED Requirements

### Requirement: 実行基盤の権限は自環境の日記データに限られる

**Reason**: 編集アプリケーションから公開手続きを起動できるようにするため、許可される権限の一覧に「自環境の公開手続きの起動と状況の読み取り」が加わる。「自環境の日記データに限られる」という名前が実態と合わなくなるため、同じ趣旨をより正確な名前で置き直した。

**Migration**: 「実行基盤の権限は自環境の日記データと公開手続きの起動に限られる」が引き継ぐ。配信元ストレージと CDN への直接の権限を与えない点、他方の環境のリソースに到達できない点は変わらない。実装上も、編集アプリケーションの実行ロールに S3 と CloudFront の権限は追加されない。
