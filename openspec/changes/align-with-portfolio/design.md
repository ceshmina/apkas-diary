## Context

動機は proposal.md（Why）を参照。要件は `specs/visual-identity/spec.md` にある。

現状の構造で、この変更に効いてくるのは次の3点である。

- **基準値の出どころは既に1つある。** `src/styles/tokens.css`（配色）と `src/styles/base.css`（本文の要素）を、公開サイトと編集アプリケーションの双方が import している。編集アプリケーションは Astro の `srcDir` だけを `editor/src` に向けており、`../../../src/styles/` を相対で読める。**要件「基準は1つの出どころを持つ」は、置き場所としては既に満たされている。** 足りないのは、そこに置かれていない値（書体・幅・角丸）と、各ページの `<style>` に散った同じ CSS のほうである。
- **`base.css` は本文の要素の見え方である。** ここに書いた `h1` `h2` `pre` は、ページの構造としての見出しと、エントリ本文の Markdown 由来の見出しの**両方**に当たる。片方だけを変えたいときは、`base.css` ではなく class で分ける必要がある。
- **ポートフォリオは別リポジトリの素の HTML + CSS である。** `../apkas/src/assets/style.css` に `:root` のトークンがあり、Web フォントを読まない方針も明記されている。ビルドの仕組みを持たないため、こちらから参照する経路はない。

## Goals / Non-Goals

**Goals:**

- ポートフォリオの `:root` にある値を、日記の基準値として持つ。
- 日記に固有の部品（入力欄・ボタン・通知・状態のピル）にも、その値から導いた体裁を与える。
- 編集アプリケーションの各ページに書き写されている同じ CSS を、1箇所へ寄せる。

**Non-Goals:**

- ポートフォリオ側と CSS を物理的に共有すること（proposal.md のスコープ外）。
- 体裁を切り替えられるようにすること（テーマの選択、色の設定）。明暗の切り替えは OS の設定に従うだけで、こちら側に選択肢を持たない。
- 既存の CSS をすべて基準値に置き換えること。1箇所にしか現れない寸法（写真の並びの間隔、拡大表示のセルなど）は、そのままにする。

## Decisions

### 1. 変数名は日記側のものを保ち、値だけを移す

`--fg` `--fg-muted` `--bg` `--accent` `--border` の名前は変えず、値をポートフォリオの `--ink` `--muted` `--bg` `--accent` `--line` に対応させる。足りない `--surface` `--accent-soft` は、ポートフォリオの名前のまま足す。対応表は `tokens.css` の先頭にコメントで残す。

- **代案：ポートフォリオと同じ名前に改名する。** 名前まで揃えても見え方は1ピクセルも変わらない。一方で、全ページの `<style>` に散った参照（`var(--fg-muted)` は12ファイル）を書き換えることになり、書き漏らすと**無言で壊れる**。CSS の未定義変数はエラーにならず、その宣言が無効になるだけで、色が消えた画面がそのまま配信される。得るものに対して落とし穴が深い。
- 名前の系統が混ざる（`--fg` と `--surface`）が、対応表があれば辿れる。

### 2. 書体・幅・角丸も `tokens.css` に置く

これまで書体は `base.css` の `body` に、幅は2つの `Base.astro` に、角丸は各ページの `<style>` に直接書かれていた。「画面ごとの独自の値」を禁じる以上、基準値として名前を持たせる必要がある。

- `--font`（書体のスタック）、`--page`（本文の幅）、`--radius` / `--radius-sm`（角丸）。
- **角丸を2段にするのは、ポートフォリオに入力欄とボタンがないため。** あちらは囲み 12px とピル 999px の2つしか持たない。12px をそのままボタンと入力欄に当てると、横に長い箱ほど角丸が目立ち、フォームだけが丸くなる。囲み 12px・ボタンと入力欄 8px・ピル 999px の3段とし、8px はこの変更で決めた値であることをコメントに残す。

### 3. 見出しの罫線は class で当てる

ポートフォリオの `.section__title` は「小さな大文字ラベル＋右へ伸びる罫線」である。日本語には大文字化が効かないため、**罫線のほうを共通の目印として持ってくる**（spec の「日本語の見出しには大文字化が効かない」に対応する判断）。

当てるのは、ページの構造としての見出しに限る。`base.css` の `h2` に直接書くと、エントリ本文の `##` にも当たり、**公開済みのエントリの見え方が変わる**。`.section-title` class を、次の3箇所の `h2` にだけ付ける。

- `src/pages/index.astro` の「年別」
- `editor/src/pages/publish.astro` の「直近の実行」
- `editor/src/pages/entries/[date].astro` の「表示の確認」

文字そのものは、ポートフォリオと同じく `--accent`・0.8rem・字間 0.2em にする。日本語2〜4文字の短いラベルであり、この大きさでも読める。長い文が来る位置ではない。

### 4. 押せるものの手応え

ポートフォリオの `.link` は、ホバーで境界線がアクセント色に変わり、2px 浮く。日記でこれをそのまま当てられるのは、**境界線を持つ箱のリンク**だけである。

- 境界線を持つ箱のリンク（編集の「今日の日記を書く」「Google でログイン」）：境界線の色＋浮き上がり。ポートフォリオと同じ。
- フォームのボタン（保存、公開する、追加する）：境界線の色だけ。押す位置が動くと、連続して押すときに狙いが外れる。
- 一覧の行・前後の導線：現状の下線のままにする。**罫線1本で区切られた行であって箱ではない**ので、浮かせると読む列が波打つ。

浮き上がりは `prefers-reduced-motion` で無効になる（`base.css` に抑制ブロックを置く）。色の変化は残るため、押せることは分かる。

### 5. 編集アプリケーションの共通 CSS は `editor/src/layouts/Base.astro` に集める

通知（`.notice`）・ボタン・入力欄・ピルの CSS が、編集アプリケーションの5〜7ページに同じ形で書き写されている。基準へ寄せるついでに、`Base.astro` の `<style is:global>` へ集約する。各ページには、その画面にしかない配置だけを残す。

- **`src/styles/base.css` には入れない。** あちらは「本文の要素の見え方」で、公開サイトも読む。フォームの部品は公開サイトに存在しない。
- **代案：`editor/src/styles/app.css` を新設する。** 骨格が既に `Base.astro` の `<style is:global>` にあり、そこに部品を足すほうが出どころが1つで済む。ファイルを分けるのは、この量では早い。

ただし**両方に現れる部品は `src/styles/base.css` に置く**。ピル（`.pill`）がこれにあたり、公開サイトの年・月の並びと、編集アプリケーションの公開状態・実行状態・差し替えの4箇所で同じものである。編集側にだけ置くと、公開サイトが同じ体裁を2度書くことになる。地を持たない側を `.pill.is-quiet` として同じ場所に置き、際立たせる/際立たせないの対を1箇所で決める。

### 6. 幅は 40rem にする

ポートフォリオの `--page: 40rem` には「日本語で 40 字/行」という根拠がコメントされている。日記の本文も日本語であり、同じ根拠が当てはまる。42rem から 2rem 狭くなるが、写真の並び（`table`）は幅に対する相対で組んであるため、比率は変わらない。

### 7. `theme-color` は2つ置く

明暗それぞれに `media` を付けた `meta` を、両方の `Base.astro` の `head` に置く。値はポートフォリオと同じ `#faf8f5` / `#15120f`。

### 8. ブラウザが自前で描く部品も基準に従わせる

ポートフォリオは入力欄を持たないため、この判断はこちら側だけのものである。日付の入力欄の暦アイコン、ラジオの印、ファイル選択のボタンは、放っておくと OS 既定の青と灰色で出る。**暗い設定では明るい前提の部品が出て、そこだけ浮く。**

- `html { color-scheme: light dark }`：ブラウザ自前の描画を明暗の設定に追従させる。
- `html { accent-color: var(--accent) }`：ラジオ・チェックボックスの印をアクセント色にする。
- `input[type='file']::file-selector-button`：ボタンの体裁を自前で与える。`accent-color` も `color-scheme` もここには効かない。

### 9. 画面の題と操作は折り返す

`.head`（画面の題＋その右の操作）と編集アプリケーションのヘッダに `flex-wrap: wrap` を与える。折り返さないと、狭い画面で**題のほうが潰れ、日本語が1文字ずつの縦棒になる**。実測（390px 幅）で「エントリ」が3行に割れていた。

操作の側を下へ回すのは、題が先に読まれるものだからである。折り返しの有無は基準の一部ではなく、この2箇所に固有の配置なので、幅の閾値を持つメディアクエリは置かない。

## Risks / Trade-offs

- **写した値が、あちらの変更で古びる** → `tokens.css` の先頭に出どころ（`../apkas/src/assets/style.css`）を書き、README の該当箇所にも同じことを書く。仕組みで防ぐ手段は持たない。ずれても壊れはせず、次に気づいたときに写し直せばよい。
- **アクセント色のピル（公開・差し替え・実行中）のコントラストが 4.23:1 になる** → `--accent` を `--accent-soft` の上に置いたときの実測値で、通常の文字に求められる 4.5:1 をわずかに下回る。これはポートフォリオの `.tags` と同じ組み合わせで、**基準を揃えた帰結**である。本文（16.4:1）、淡い文字（5.4:1）、地の上のアクセント（4.9:1）はいずれも満たしている。ピルが示す状態は、その行や見出しの文脈からも読めるため、ここだけ別の色を作ることはしない。
- **公開済みのエントリの折り返し位置が変わる** → 幅が 2rem 狭くなるため。整形の規則（`src/lib/markdown.ts`）は変えないので、内容と要素の対応は変わらない。
- **アクセント色が青からテラコッタになり、リンクが「押せるもの」に見えにくくなる可能性** → 日記のリンクは下線を持たず色だけで示している。テラコッタは地の文（`#1c1a18`）と色相が近い。一覧の行と前後の導線ではホバーの下線で補えるが、本文中のリンクにはそれがない。staging で実際のエントリを見て確かめる。
- **各ページの `<style>` を `Base.astro` へ集約する際、拾い漏らす** → 集約後に `editor/src/pages/` を横断して、残った宣言が「その画面にしかない配置」だけであることを確認する。

## Migration Plan

デプロイの経路は既存のまま（公開サイトは `npm run build` → `npm run deploy`、編集アプリケーションは `npm run deploy:editor`）。データにも構造にも触れないため、移行の手続きはない。

1. staging にデプロイし、公開サイトと編集アプリケーションの双方を、明暗それぞれの設定で確認する。
2. 実データのエントリ（写真の並びを含むもの、Markdown の見出しを含むもの）で本文の見え方を確認する。
3. production へ反映する。

戻すときは revert して同じ経路でデプロイし直す。配信物が入れ替わるだけで、途中の状態は残らない。
