## Why

旧サイト（eskarun）から日記を移行したとき、frontmatter の `location`（**107件・33地点**）だけを取り込まなかった。「この日記は場所を扱わない」という判断であり、元のファイルが残るので読み直せる、という前提を置いていた（`migrate-legacy-diary` の proposal - スコープ外）。

その前提が細っている。旧サイトのリポジトリは公開されておらず、いまこの情報は手元のクローン1つにしかない。日記本文と写真は DynamoDB を正として Markdown にも書き出し、写真は元写真ごと保全してあるのに、**どこで書いた日かという記録だけが、その保全の外にある**。旧ホストの廃止に向けて旧基盤を畳んでいく過程で、これが最後に残った未移行の情報になった。

移行の取りこぼしを埋めるだけなら取り込んで終わりだが、取り込んだ先が読めず書けずでは、保全した瞬間に死んだ属性になる。**場所を扱う**と決めて、書く・読む・保全するの3つを揃える。

## What Changes

- **エントリが場所の属性を持てるようにする**。`Osaka, Japan` のような旧サイトの表記をそのまま1つの文字列として保持する。都市と国に分解しない。国別の集計が必要になったときに、そのときの必要に合わせて考える。
- **場所は任意の属性とする**。書いていないエントリは未指定のまま保持し、値を埋めない。旧サイトは未指定を `Tokyo, Japan` とみなして表示・集計していたが、**書いていないことと東京にいたことは違う**。既定値は持たず、表示にも出さない。
- **編集アプリケーションと CLI から場所を入力・変更できるようにする**。今後書く日記にも場所を付けられる状態にする。
- **公開サイトの日別ページに場所を表示する**。場所を持つエントリだけに現れる。
- **書き出し（export）に場所を含める**。エントリの属性が1つ増えても、書き出したファイルだけで日記の全体が読める状態を保つ。
- **旧サイトの 107件の場所を取り込む**。既存の取り込み CLI（`import-legacy`）が `location` を読むようにし、本文・タイトル・公開状態を書き換えずに場所だけを埋める経路を用意する。

### スコープ外

- **場所別の一覧・集計ページ**。旧サイトは地点ごとの記事一覧と、日本・国外に分けた集計を持っていた。この change は属性を持ち、書け、読めるところまでとする。一覧は日記の見せ方の話であり、属性の保全とは別に決められる。
- **場所の正規化・候補からの選択**。表記の揺れ（`Tokyo, Japan` と `tokyo,japan` など）は起こりうるが、書き手は1人で、旧サイトの33地点に揺れは無い。仕組みで縛るより、必要になってから足すほうが軽い。
- **未指定のエントリへの遡及的な補完**。移行対象は旧サイトが実際に書いていた107件だけとする。
- **写真の撮影地**。写真の目録が持つ EXIF とは別の話で、この change では扱わない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `diary-entry-store`: エントリの属性に場所を加える。任意であること、未指定と空文字を区別せずに「持たない」として扱うこと、値を解釈せず文字列のまま保持することを要求に加える。
- `entry-editing`: 編集アプリケーションから場所を入力・変更・削除できることを要求に加える。
- `diary-site-pages`: 日別ページに場所を表示すること、持たないエントリには何も出さないことを要求に加える。
- `content-export`: 書き出したファイルから読めるものに場所を加える。書き出しだけで日記の全体が読める、という要求の対象に新しい属性を含める。

## Impact

**アプリケーション**

- `src/lib/store/entry.ts`: `Entry` に `location?` を加え、DynamoDB アイテムとの相互変換で付け外しする。
- `src/lib/store/put.ts`: `putEntry()` の入力に場所を加える。省略時は既存値を引き継ぎ、明示的な削除と区別する。
- `src/export/markdown.ts`: frontmatter に `location` を出す。持たないエントリでは行そのものを出さない（書き出しの冪等性を保つ）。
- `src/pages/[year]/[month]/[day].astro`: 場所の表示。
- `editor/src/pages/entries/[date].astro`: 入力欄と保存。
- `src/cli/put-entry.ts`: `--location` オプション。
- `src/legacy/source.ts`・`src/cli/import-legacy.ts`: `location` の読み取りと、場所だけを埋める取り込み。

**データ**

- production の DynamoDB で 107件のエントリに属性が1つ増える。本文・タイトル・公開状態・`createdAt` は変わらない。`updatedAt` は更新される。
- 残り 1,000件あまりのエントリは変わらない（属性を持たないまま）。

**配信物**

- 場所を持つ107日の日別ページのマークアップが変わる。他のページは変わらない。

**リポジトリ外**

- 取り込み元として `../eskarun` のクローンが要る。取り込みが済めば、この情報は DynamoDB と書き出しの双方に入る。
