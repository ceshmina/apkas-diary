## Why

apkas-diary はまだ README しかない空のリポジトリで、日記を1件も保存できない。まず「書いたものが失われず、公開サイトとして読める」最小の土台を用意する。

土台の作り方には長期的な制約がある。日記は**アプリのコードより寿命が長い**データで、10年後に読み返せることが要件に含まれる。したがってこの change では、機能の多さではなく「データが正しい場所に、正しい形で、失われずに置かれること」を優先する。書き込み手段（管理画面・スマホからの編集）は後続の change に譲り、最初は手動登録で成立させる。

## What Changes

- **日記データのストアを DynamoDB に置く**。データの正は DynamoDB とし、静的サイトはその射影として扱う。1日1件・シングルテーブル設計・オンデマンド課金・PITR 有効。
- **公開サイトを Astro で静的生成する**。ビルド時に DynamoDB から全件取得し、トップ・日別・年別・月別・「N年前の今日」のページを生成する。閲覧に認証は不要な一般公開サイトとする。
- **配信を S3 + CloudFront で行う**。S3 バケットはパブリックアクセスを全ブロックし、CloudFront から OAC 経由でのみ読めるようにする。ビルドとデプロイはローカルから実行する。
- **ビルドの副産物として日記本文を Markdown で書き出す**。DynamoDB や AWS アカウントを失っても日記がプレーンテキストで残ることを担保する。全件取得は既に行っているため追加コストはない。書き出し先はバージョン管理の対象外のローカルディレクトリとし、リポジトリにはコミットしない。
- **インフラを Terraform で管理し、staging と production の2環境を用意する**。環境は `AWS_PROFILE` で切り替える。
- **下書きを sparse index で公開対象から外す**。`status` が `draft` のあいだは GSI のキー属性そのものを書かないことで、公開ビルドから下書きが漏れる経路を構造的に塞ぐ。

## Capabilities

### New Capabilities

- `diary-entry-store`: 日記エントリの保存形式、キー設計、アクセスパターン、日付の扱い、下書きと公開の区別、バックアップ方針
- `diary-site-pages`: 公開サイトが提供するページの種類と、各ページが何を表示するか
- `content-export`: ビルド時に日記本文を可搬なプレーンテキストとして書き出し、データの長期保全を担保する
- `site-delivery`: 静的サイトの配信経路とアクセス制御。S3 を直接公開せず CloudFront 経由に限定する
- `deployment-environments`: staging と production の分離、環境ごとのリソース命名、認証情報の切り替え、Terraform state の管理

### Modified Capabilities

（なし。`openspec/specs/` は空で、既存の capability は存在しない）

## Impact

- **新規リポジトリ構成**: `terraform/`（`modules/` と `envs/`）、Astro のフロントエンド、ビルド時にデータを取得するスクリプト、書き出された Markdown の置き場（バージョン管理対象外）
- **AWS リソース**: DynamoDB テーブル、S3 バケット（サイト配信用）、CloudFront ディストリビューション、OAC、Terraform state 用の S3 バケット。いずれも staging / production の2セット
- **前提となるツール**: Node.js 22（導入済み）、Terraform 1.10 以降（S3 バックエンドのネイティブロックを使うため）、AWS CLI と2つの named profile
- **運用コスト**: 個人利用の規模では DynamoDB オンデマンド・S3・CloudFront のいずれも従量課金の下限付近に収まる見込み
- **既存コードへの影響**: なし（新規構築）

## 非目標

この change には含めない。いずれも後続の change で扱う。

- 管理画面、およびスマホからの編集
- API Gateway / Lambda による書き込み経路
- 写真のアップロードと配信
- タグ機能
- 全文検索
- 「N年前の今日」用の GSI2（必要になった時点でオンライン追加する）
- DynamoDB Streams を起点とした自動リビルド
- CI/CD パイプライン
