## Why

日記の本文には写真が多く並ぶ。本文の幅は 42rem（672px）に固定されているため、写真はその幅まで縮めて表示される。実際の画像は 1920×1280 あり、画面に出ているのはその3分の1ほどの大きさでしかない。写真の細部は配信されているのに読み手には届いていない。

いま大きく見る手段は、画像の URL を直接開くことだけである。別のタブに写真だけが表示され、日記の文脈からは切り離される。読んでいる流れを保ったまま、その場で大きく見られるようにしたい。

## What Changes

- 日別ページの本文中の写真をクリック（タップ）すると、画面いっぱいに拡大して表示する。開くときも閉じるときも、写真が元の位置から動く様子をアニメーションで繋ぐ。
- 閉じる操作は、もう一度のクリック、Esc、そして**上下どちらかへの十分な量のドラッグ（スクロール）**の3つ。ドラッグの途中では写真が指に追従し、動かした量が閾値に届かないまま離せば拡大状態に戻る。
- 同じ日記に複数の写真があるとき、**拡大したまま左右のドラッグで前後の写真へ移れる**。キーボードの左右キーでも同じように移る。並びは本文に現れる順で、`figure` の1枚も `table` で横に並んだ写真も区別なく1つの並びとして扱う。
- 並びの端では折り返さない。最初の写真で前へ、最後の写真で次へ動かそうとしても、抵抗のかかった動きのあとで元に戻る。何枚目を見ているかが指の手応えで分かる。
- 対象は本文中の写真すべて。`![](…)` から作られる `figure` の中の1枚も、旧サイトから引き継いだ `table` で横に並んだ写真も、同じように開く。
- 写真に添えられた説明（`figcaption`）は、拡大しているあいだも読める位置に出す。本文に書かれた文が画面から消えないことは、この日記が既に守っている原則である。
- 拡大表示では large（3840×2560）に差し替える。開く動作そのものは既に読み込まれている medium で即座に行い、large は読み込めた時点で静かに置き換える。差し替えに失敗しても、medium を拡大したままの表示に留める。
- 閲覧のための JavaScript をこのサイトに初めて導入する。JS が動かない環境では現在とまったく同じページになる。写真は本文の幅で表示され、押せるという見た目の手がかりも現れない。

### スコープ外

- 一覧ページ・月日ページ。いずれも日付とタイトルだけを並べており、写真を出していない。
- 日記をまたぐ写真の移動。左右で移れるのは同じ日記の中の並びに限る。日記から日記への移動は既に前後の導線が担っており、写真の並びをその上に重ねると、同じ操作が2つの階層を跨ぐことになる。
- 任意倍率のズームとパン（ピンチ操作）。画面に収まる大きさまでの開閉に限る。それ以上を求める読み手には、画像を直接開くという既存の手段が残る。
- 本文中の写真の出し分け（`srcset` や遅延読み込み）。本文の初期表示は今のまま変えない。
- 写真ホスト（`photos.old.apkas.net`）側の変更。既にある `/medium/` と `/large/` をそのまま使う。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `diary-site-pages`: 日別ページの本文中の写真を拡大して見られる要件と、拡大したまま同じ日記の他の写真へ移れる要件を足す。あわせて、拡大の仕掛けが JavaScript に依存する一方で、本文と写真そのものの閲覧は依存してはならないことを要件に含める。「静的に生成され、閲覧に認証を要さない」ことをサイトの前提として既に spec に持っているので、閲覧が動くスクリプトを前提としないことも同じ場所に残しておきたい。

## Impact

**アプリケーション**

- `src/pages/[year]/[month]/[day].astro`: 本文に開閉の仕掛けを付ける。既にある `.body` の画像まわりのスタイルと隣り合う。
- 開閉と移動の仕掛け（スクリプトとスタイル）を収める新しいコンポーネントを足す。

**配信物**

- 日別ページに小さなスクリプトが1つ増える。HTML の構造も URL の集合も変わらない。
- 拡大したときにだけ `photos.old.apkas.net/large/` を読む。1枚あたり約500KB で、開いた写真と、そこから移った写真の分だけ発生する。本文の初期表示で読む画像は変わらない。

**外部への依存**

- 写真ホストの `/medium/` と `/large/` が同じ相対パスで対応するという URL 規約に依存する。この規約は旧サイトのもので、この change では検証しかできない。対応する large が無い写真があっても表示が壊れないよう、差し替えの失敗は無視する。
