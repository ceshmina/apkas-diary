## Purpose

生成された派生画像を閲覧者に届ける経路を定め、その経路以外から配信元に到達できないことを担保する。あわせて、日記本文に書かれた URL が長く指し続けられるよう、URL の組み立て規約を固定する。

## ADDED Requirements

### Requirement: 写真は CDN 経由で一般公開される

写真は CDN を通じて配信され、閲覧に認証を要求してはならない（MUST NOT）。

日記本文は誰でも読める。そこに埋め込まれた写真だけが認証を求めるなら、本文は読めるのに絵だけが欠けたページになる。

#### Scenario: 訪問者によるアクセス

- **WHEN** 訪問者が日記のページを開き、本文に埋め込まれた写真が読み込まれる
- **THEN** 認証なしで写真が表示される

### Requirement: 写真は環境ごとに定められた独自ドメインで配信される

写真は、配信基盤が自動で払い出す名前ではなく、環境ごとに定められた独自ドメインで到達できなければならない（MUST）。環境が異なればドメインも異なっていなければならない（MUST）。

独自ドメインでの通信には、そのドメインに対して有効な証明書が提示されなければならない（MUST）。

#### Scenario: 独自ドメインでのアクセス

- **WHEN** 訪問者が環境の写真配信ドメインで写真を要求する
- **THEN** その環境に投入された写真が配信される

#### Scenario: 証明書の検証

- **WHEN** 訪問者が写真配信ドメインに HTTPS で接続する
- **THEN** そのドメインに一致する有効な証明書が提示され、警告なく接続が確立する

#### Scenario: 環境ごとのドメイン

- **WHEN** staging と production の写真配信ドメインを確認する
- **THEN** 互いに異なるドメインである

#### Scenario: 配信基盤の作り直し

- **WHEN** 写真の配信基盤を作り直し、自動で払い出される名前が変わる
- **THEN** 日記本文に書かれた写真の URL は変わらないまま、同じ写真を指し続ける

### Requirement: 写真の URL はサイズ名と元写真のキーから決まる

写真の URL は、**サイズ名を先頭に置き、その後ろに元写真のキーを拡張子だけ置き換えて続ける**形でなければならない（MUST）。

```
https://<配信ドメイン>/<サイズ名>/<元写真のキーの拡張子を webp に替えたもの>
```

サイズ名は `thumbnail` / `small` / `medium` / `large` のいずれかである。

この規約は、旧ホストが持っていた「サイズを先頭に置く」形を引き継ぐものである。

#### Scenario: URL の組み立て

- **WHEN** キー `2026/08/08/IMG_1234.jpg` として投入された写真の `medium` を要求する
- **THEN** `https://<配信ドメイン>/medium/2026/08/08/IMG_1234.webp` でその写真が得られる

#### Scenario: 元写真の形式によらない URL

- **WHEN** キー `2026/08/08/scan.png` として投入された写真を要求する
- **THEN** URL の拡張子は元の形式によらず `.webp` である

### Requirement: サイズ名を差し替えれば同じ写真の別のサイズが得られる

同じ写真の4つのサイズは、URL のうちサイズ名の部分**だけ**が異なっていなければならない（MUST）。それ以外の部分が一致していないサイズがあってはならない（MUST NOT）。

参照する側は、ある1つのサイズの URL を持っていれば、問い合わせなしに他のサイズの URL を導ける。日別ページの写真の拡大表示は、既にこの形の規約に依存している。

#### Scenario: サイズ間の対応

- **WHEN** ある写真の `medium` の URL を得て、`medium` の部分を `large` に置き換えて要求する
- **THEN** 同じ写真の `large` が返る

#### Scenario: 4つのサイズの到達性

- **WHEN** 投入された写真について、4つのサイズ名すべてで URL を組み立てて要求する
- **THEN** いずれも同じ写真の、それぞれの大きさの画像を返す

### Requirement: 配信元のストレージは直接アクセスできない

配信元のオブジェクトストレージはパブリックアクセスを全面的に禁止し、CDN からのみ読み取れるように制限しなければならない（MUST）。元写真を置くストレージも同様に、パブリックアクセスを禁止しなければならない（MUST）。

#### Scenario: 配信元ストレージへの直接アクセス

- **WHEN** 配信元バケットのオブジェクト URL に直接アクセスする
- **THEN** アクセスが拒否される

#### Scenario: CDN 経由のアクセス

- **WHEN** 同じオブジェクトに CDN 経由でアクセスする
- **THEN** 正常に配信される

#### Scenario: アップロード先ストレージへの直接アクセス

- **WHEN** 元写真を置くバケットのオブジェクト URL に直接アクセスする
- **THEN** アクセスが拒否される

### Requirement: 通信は HTTPS に限定する

写真への通信は暗号化されなければならない（MUST）。

日記のページは HTTPS で配信される。そこに HTTP の写真を混ぜると混在コンテンツになり、写真が表示されない。

#### Scenario: HTTP でのアクセス

- **WHEN** 訪問者が HTTP で写真を要求する
- **THEN** HTTPS にリダイレクトされる

### Requirement: 存在しない写真の要求では画像が返らない

投入されていない写真の URL に対して、画像を返してはならない（MUST NOT）。要求はエラーとして扱われなければならない（MUST）。

配信元に置かれたオブジェクトの一覧が返ってはならない（MUST NOT）。どの写真が存在するかは、URL を1つずつ試す以外の方法で外から数え上げられてはならない。

#### Scenario: 存在しないキー

- **WHEN** 投入されていないキーの URL を要求する
- **THEN** エラーが返り、画像は返らない

#### Scenario: 定義されていないサイズ名

- **WHEN** `thumbnail` / `small` / `medium` / `large` 以外のサイズ名で URL を組み立てて要求する
- **THEN** エラーが返り、画像は返らない

#### Scenario: 一覧の取得

- **WHEN** 配信ドメインの根や、サイズ名だけのパスを要求する
- **THEN** 配信元に置かれたオブジェクトの一覧は返らない

### Requirement: 写真は長期にキャッシュされ、作り直しは配信に反映される

同じ URL の写真は繰り返し配信されるため、長期にキャッシュされてよい（MAY）。

ただし元写真が投入し直され、派生画像が作り直された場合、CDN が古い内容を配信し続けてはならない（MUST NOT）。

#### Scenario: 繰り返しの閲覧

- **WHEN** 同じ写真を含むページを2度開く
- **THEN** 2度目の写真の取得は CDN のキャッシュから満たされる

#### Scenario: 写真の差し替え

- **WHEN** すでに配信されているキーに、別の内容の元写真を投入し直す
- **THEN** その後の要求には新しい内容が配信される

### Requirement: 写真の配信は日記サイトの配信から独立している

写真の配信経路は、日記サイトの配信経路とストレージを共有してはならない（MUST NOT）。一方への操作が他方の配信内容を変えてはならない（MUST NOT）。

日記サイトのデプロイは配信元を丸ごと同期し、生成物にないものを削除する。写真が同じ場所にあれば、サイトを1度デプロイするだけで全部消える。

#### Scenario: サイトのデプロイ

- **WHEN** 日記サイトを生成し直してデプロイする
- **THEN** 配信中の写真はいっさい影響を受けない

#### Scenario: 写真の投入

- **WHEN** 写真を投入する
- **THEN** 日記サイトの配信物はいっさい変化しない
