## MODIFIED Requirements

### Requirement: 日別ページで個々のエントリを読める

各エントリは `/<年>/<月>/<日>` の形式のパスで読めなければならない（MUST）。月と日は2桁のゼロ埋めとする。

タイトルを持たないエントリは日記の過半を占めうる。タイトルの不在を欠落として示してはならない（MUST NOT）。

エントリの日付は、そのページに1度だけ表示されなければならない（MUST）。日付の書式は、タイトルの有無によって変えてはならない（MUST NOT）。

#### Scenario: 公開エントリの日別ページ

- **WHEN** 訪問者が公開済みエントリの日付のパス（例 `/2026/08/01`）にアクセスする
- **THEN** そのエントリの日付・タイトル・本文が表示され、本文は Markdown を整形した形で表示される

#### Scenario: タイトルを持たないエントリ

- **WHEN** 訪問者がタイトルを持たないエントリの日別ページにアクセスする
- **THEN** そのエントリの日付が見出しとして表示され、タイトルが空であることを示す文言は現れない

#### Scenario: 日付の表示は1度きり

- **WHEN** タイトルを持つエントリと持たないエントリの日別ページをそれぞれ表示する
- **THEN** どちらのページでも日付は同じ書式で1度だけ現れ、同じ日付が2箇所に重複して表示されることはない

#### Scenario: エントリのない日付

- **WHEN** 訪問者がエントリの存在しない日付のパスにアクセスする
- **THEN** 404 が返る

#### Scenario: 下書きの日付

- **WHEN** 訪問者が下書き状態のエントリしかない日付のパスにアクセスする
- **THEN** 404 が返り、下書きの存在は判別できない

### Requirement: 本文は Markdown として整形して表示する

エントリ本文は Markdown として解釈し、整形された形で表示しなければならない（MUST）。

本文には、Markdown で表せない配置のために HTML が直接書かれている場合がある。表示側はそれを取り除いてはならず（MUST NOT）、読める形で整形しなければならない（MUST）。

本文に書かれた文が画面に現れないまま失われてはならない（MUST NOT）。

#### Scenario: Markdown の整形

- **WHEN** 見出し・箇条書き・リンクを含む本文を持つエントリの日別ページを表示する
- **THEN** それぞれが対応する要素として整形されて表示される

#### Scenario: 画像に添えられた説明

- **WHEN** 画像に説明を添えた本文（`![説明](画像のURL)`）を表示する
- **THEN** その説明が画像に添えられた文として画面に表示される

#### Scenario: 文章の途中に置かれた画像

- **WHEN** 段落の文章の途中に画像が置かれた本文を表示する
- **THEN** 段落は分断されず、文章の流れが保たれる

#### Scenario: 本文中に直接書かれた画像の並び

- **WHEN** 画像を横に並べる目的で `table` として書かれた HTML を含む本文を表示する
- **THEN** 画像が横に等しい幅で並び、行全体に及ぶセルはその並びに対する説明として表示される

#### Scenario: 狭い画面幅での表示

- **WHEN** 横に並んだ画像を含むページを狭い画面幅で表示する
- **THEN** 横方向にはみ出さず、画面の幅に収まる
