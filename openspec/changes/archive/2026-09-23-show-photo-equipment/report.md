# 実施の記録

## 目録に何が入っていたか

**production の写真 2,416枚は、全枚数が `exif` を持っていた**（記録の無いものは0枚）。旧サイトから移した2,365枚も含めてである。`migrate-legacy-photos` の report.md が「撮影情報が失われた写真は1枚も無い」と書いていたとおりで、design.md の Open Questions の1つ目はこれで閉じた。**過去の日記にも一様に出る。**

機種は16。レンズを交換する7つと、コンパクト機・スマートフォン8つ、それに写真アプリが1つ。

| 分類 | 機種 |
| --- | --- |
| レンズを交換する | `ILCE-7M3` / `ILCE-7RM5` / `ILCE-7S` / `ILCE-7CM2` / `E-P7` / `DC-GF9` / `NIKON D5600` |
| レンズを選べない | `DSC-RX1RM3` / `RICOH GR III` / `RICOH GR IIIx` / `LEICA D-Lux 8` / `X100VI` |
| スマートフォン | `iPhone 15 Pro` / `iPhone 12` / `XQ-GE44` |
| 写真アプリ | `foodie`（`Make` は `Snowcorp`） |

## 途中で分かったこと

**1. `lensModel` が `model` を含むかだけでは分けられない。** 当初の設計は値どうしの関係だけで決める形だったが、production の目録で成り立たないことが分かった。

| 機種 | `lensModel` | 枚数 |
| --- | --- | --- |
| `DSC-RX1RM3`（レンズを選べない） | `35.0 mm f/2.0` | 249 |
| `NIKON D5600`（レンズを交換する） | `18.0-55.0 mm f/3.5-5.6` ほか2本 | 38 |

字面が同じ形で、望ましい結果が逆になる。**レンズを出さない機種を系列の名前で持つ**形に変えた（design.md 決定5 を書き直し、spec も直した）。系列で持つのは、メーカーが固定レンズと交換式を系列名で分けているためである（Sony の `DSC-` と `ILCE-`、富士フイルムの `X100` と `X-T`）。

**2. EXIF の文字列が NUL で終端されている機種がある。** `RICOH GR IIIx\u0000` が production に39枚。`trim()` は NUL を落とさないので、**気づかなければ NUL がそのままページに載っていた**。制御文字を先に外す処理を足した。

**3. 生の HTML の `<img>` は木の `img` にならない。** 旧サイトから引き継いだ記事は画像を横に並べるために `table` を本文に直接書いており、そこを外すと過去の写真の大半に機材が出ない。`raw` の visitor で、その1タグだけに属性を足した。生の HTML を解釈して木に変えると、素通りしていた1,000件近い記事の出力がこの change のついでに変わりうる。

**4. レンズの接点を持たない機材は `----` と書く**（8枚）。「読めなかった」を書き写した値であって、レンズの名前ではないので落とす。

**5. 公開手続きのボタンは `main` の最新を配る。** `source_version = refs/heads/main` で、この change が main に入るまでは押しても変更前のサイトが配られる（`site-publishing` の「共有された版に由来する」が効いている）。**権限が足りているかをボタンで確かめることはできなかった**ので、IAM のポリシーシミュレータで実行ロールを直接評価した。

| 主体 | 操作 | 対象 | 結果 |
| --- | --- | --- | --- |
| 公開手続きの role | `Query` | ベーステーブル + `LeadingKeys = PHOTO#…` | allowed |
| 同上 | `Query` | ベーステーブル + `LeadingKeys = ENTRY#…` | **implicitDeny** |
| 同上 | `Query` | GSI1 | allowed（従来どおり） |
| 同上 | `Scan` | ベーステーブル | allowed（従来どおり） |
| 同上 | `PutItem` / `UpdateItem` / `DeleteItem` | ベーステーブル | implicitDeny（従来どおり） |

staging・production の双方で同じ結果。**下書きを含むエントリの取得経路は、コードだけでなく IAM でも閉じている。**

## 触っていないもの

- 日記の本文・写真の目録。**この change は読むだけである。**
- 編集アプリケーションのプレビュー。書き出した staging の本文25件を変更前後の `renderMarkdown` に通して、差分が0件であることを確かめた。

## 残っていること

**公開手続きのボタンからの通し。** main に取り込んだあとに書き手が行う。ボタンが配るのは `main` の最新なので、この change が入るまでは押しても変更前のサイトが配られる。権限が足りていることは、ポリシーシミュレータで staging・production の双方について確かめてある（上記）。

描画の目視（説明と機材の見え方、移動での入れ替わり、スクリプトを止めたときの姿）は、staging と production の双方で**書き手が済ませた**。
