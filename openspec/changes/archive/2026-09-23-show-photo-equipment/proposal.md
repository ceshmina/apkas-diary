## Why

写真の目録は、投入されたすべての写真について撮影機材を記録している（`photo-catalog`「撮影に関する情報が記録される」）。読み取りは派生画像を作る過程で、付随情報を除去する**前**に行われる。旧サイトから移した 2,365 枚についても「撮影情報が失われた写真は1枚も無い」（`migrate-legacy-photos` の report.md）。

**それでいて、この情報はまだどこからも読まれていない。** 保全のためだけに書かれ、誰の目にも触れていない属性がひとつある状態が続いている。

日記を読み返すとき、どのカメラを持って出た日かは本文に書かれていない。書く気も起きない類の情報で、書けと言われれば書かなくなるほうに倒れる。けれど写真そのものが既にそれを持っており、こちらは書かずに手に入れている。**日記に手を入れずに読めるものが増える**というのは、日記を長く続けるうえで数少ない、ただで手に入るものである。

置く場所は拡大表示とする。拡大は写真1枚と向き合う唯一の場所であり、そこでだけ1枚に属する情報が意味を持つ。本文に出すと、1枚ごとの短い文字列が読みの流れを刻む——本文は日記を読むための場所であって、写真の明細を読むための場所ではない。

## What Changes

- **日別ページの拡大表示に、その写真の撮影機材を表示する**。1行・カンマ区切りで、写真そのものに添えられた説明（キャプション）の下に置く。
- **出す字面は機材の種類で変える**。スマートフォンのように、レンズの名称が機種の名称を含んでいる場合はレンズを出さず、機種名だけを出す（`iPhone 15 Pro`）。レンズを交換する機材では機種名とレンズ名を並べる（`X-T5, XF33mmF1.4 R LM WR`）。**機種の一覧をコードに持たない。** 記録されている値どうしの関係だけで決める。
- **機材の記録がない写真には、機材に関わる表示を出さない**。行そのものを出さず、空の行も「不明」の類の文言も置かない。タイトル・場所の不在と同じ扱いとする。
- **説明より薄い色で置く**。同じ画面に2種類の文字が並ぶので、どちらが著者の言葉でどちらが機械の記録かが、読む前に色で分かる状態にする。
- **公開サイトのビルドが写真の目録を読むようにする**。いまサイト生成の入力はエントリ（GSI1 の Query 1本）だけで、写真は索引に載っていない。本文に現れる写真の属する日だけを、日付ごとに引く経路を1つ足す。

### スコープ外

- **焦点距離・絞り・シャッター速度・ISO 感度**。目録は記録しているが、今回は出さない。機材は「その日の持ち物」だが、露出は1枚ごとの設定であり、読み返しの役に立つ度合いが違う。出すと決めたときに足せる（記録は既にある）。
- **撮影日時**。日記は暦日で書かれており、その日付は既にページの見出しに1度出ている。写真ごとの時刻を足すと、同じ日を指す表示が2つになる。
- **本文（拡大していない状態）への表示**。上記のとおり、本文は読みの場である。
- **機材別の一覧・集計**。「このカメラで撮った日」を辿れると面白いが、それは日記の見せ方を1つ増やす話で、表示とは別に決められる。
- **編集アプリケーションのプレビュー**。プレビューは本文の整形を確かめるためのもので、拡大の仕掛けを持たない。
- **機材名の正規化・和訳**。`ILCE-7M4` を `α7 IV` に読み替えるような対応表は持たない。記録されたままを出す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `diary-site-pages`: 「日別ページの本文中の写真を拡大して見られる」に、拡大している写真の撮影機材が読めること、記録のない写真には何も出さないこと、著者の説明と機械の記録が見分けられることを要求として加える。

## Impact

**アプリケーション**

- `src/lib/photo.ts`: 配信 URL から元写真のキーを逆に導く関数を足す（`photoUrlOf` の逆）。本文に書かれているのは URL だけなので、目録を引くための日付とファイル名はそこから取り出す。
- `src/lib/site-data.ts`: サイト生成の入力に写真の目録を加える。エントリの取得と同じくビルド中に1度だけ引き、日付で重複を畳む。
- `src/lib/markdown.ts`: 整形した木の `img` に、機材の字面を `data-` 属性として載せる。本文そのものは書き換えない。
- `src/pages/[year]/[month]/[day].astro`: 整形に、その日の写真の機材を渡す。
- `src/components/photo-zoom.ts`・`src/components/PhotoZoom.astro`: 拡大表示のセルに機材の行を足す。説明と同じ扱いで、移動・閉鎖のたびに入れ替わる。

**基盤**

- `terraform/modules/publish`: 公開手続きの role に、**目録のパーティションに限った**ベーステーブルへの Query を足す。いまこの role が持つ Query は GSI1 の ARN だけで、「ベーステーブルへの Query は与えない」と明記されている。写真の目録はベーステーブルにあり、索引には載らない（sparse index）ため、権限を足さなければ公開手続きだけが失敗する。**エントリのパーティションは引けないままにする。**

**データ**

- 変更なし。目録も日記も書き換えない。**読むだけの change である。**

**配信物**

- 写真を含む日別ページの `img` に `data-` 属性が増える。機材の記録がない写真では増えない。
- 拡大表示の中身はスクリプトが組み立てるため、静的な HTML の見た目は変わらない。

**ビルド**

- 写真を含む日ごとに、目録への Query が1本増える（写真の枚数ではなく、写真のある日の数だけ増える）。同時に走らせる本数には上限を置く。
