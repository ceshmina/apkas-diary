## Context

動機は [proposal.md](proposal.md) の Why にある。ここでは、あちらの新しい組み方を日記のどの要素に当てるかと、装飾を削ったときに日記の側で何が起きるかを決める。

出どころは `../apkas/src/assets/style.css`、変更は同リポジトリの `b88559d`。あちらの判断は3つに要約できる。

1. **Web フォントは増やさない。** OS 標準の明朝とゴシックを使い分けることで階層をつける。
2. **明朝は、名前・本文・見出しだけ。** 0.9rem 以下のラベルや注記は、明朝ではかすれるためゴシックに寄せる。
3. **装飾を削る。** 角丸 12px → 2px、タグは塗りつぶしから細い枠へ、経歴の点は塗りから輪郭へ、リンクのホバーの浮き上がりは廃止。

制約は前回・前々回から変わらない。別リポジトリ・別配信なので CSS は共有できず、日記は写しを持つ。日記の中では `src/styles/tokens.css`（色と寸法）と `src/styles/base.css`（字送りと本文要素）が1つの出どころで、公開サイトと編集アプリケーションはこれを共に読む。

日記にはあちらにない事情が2つある。

- **本文の量が桁違いに多い。** あちらの本文は数段落だが、日記は 1119 件のエントリすべてが本文である。明朝を当てる範囲の決め方が、そのままサイト全体の印象になる。
- **同じ本文が2箇所に現れる。** 公開サイトの日別ページと、編集アプリケーションのプレビューである。`visual-identity` はこの2つが同じ字面で現れることを要件にしている。

## Goals / Non-Goals

**Goals:**

- 明朝とゴシックの使い分けが、あちらと同じ規則（名前・本文・見出しは明朝、0.9rem 以下はゴシック）で説明できること。要素ごとの好みで決めた箇所が残らないこと。
- エントリ本文の体裁が1箇所にあり、プレビューと公開後で同じ字面になること。
- ピルの塗りをやめたあとも、際立たせる側とそうでない側が、色相だけに頼らずに見分けられること。
- 日記の側で新しい基準値を作らないこと。むしろ、前回こちらで作った `--radius-sm` を、理由が消えたので手放すこと。

**Non-Goals:**

- 配色に触れること。あちらでも変わっていない。
- ページの構成・余白・本文の幅を変えること。
- 明朝の載っていない環境のために代替を用意すること。総称 `serif` への落ち方はあちらと同じでよい。

## Decisions

### 決定1：地はゴシックのまま、明朝は名指しした要素だけに当てる

あちらは `body` をゴシックにしたうえで、明朝にする要素を選択子で列挙している。日記も同じ形を取る。逆（`body` を明朝にして小さい要素をゴシックへ戻す）にはしない。列挙されていない要素が黙って明朝になり、そのたびに例外を足すことになる。

当てる先の対応は次のとおり。

| ポートフォリオ | 日記 | 大きさ |
| --- | --- | --- |
| `.hero__name`（名前） | `.site-title` / `.app-title`（サイトの題） | 1.1rem |
| `.card__title` / `.timeline__title`（見出し） | `h1` / `h2` | 1.5rem / 1.2rem |
| `.prose` / `.hero__lede`（本文） | `.prose`（エントリ本文・404 の文） | 1.05rem |
| `.link__label`（並んだリンクの題） | 一覧のエントリ題（`.entry-title`） | 1rem |

あちらと同じく `font-weight: 500` を添える。游明朝は太さの指定がないと Light を拾って痩せて見える。`font-feature-settings: "palt" 1` は名前と見出し（サイトの題・`h1` / `h2`・エントリ題）にだけ当てる。あちらも本文（`.prose` / `.hero__lede`）には当てていない。約物を詰めるのは字面を締めるためで、長い本文で行うものではない。

**ゴシックのまま残すもの**は、あちらの「0.9rem 以下」の線をそのまま使う。日付、件数、節の題、ピル、フォームの見出しと入力欄、画像の説明、前後の導線。前後の導線（`.adjacent`）は 0.9rem なので、中のエントリ題も明朝にしない。**一覧は 1rem、導線は 0.9rem** という既にある差が、そのまま線引きになる。

**代替案：エントリ題は場所によらず明朝にする。** 採らない。導線の 0.9rem で明朝を使うことになり、あちらが避けた大きさに自分から入る。

**代替案：見出しだけ明朝にして本文はゴシックのまま。** 採らない。あちらの本文（`.prose`）は明朝であり、日記の本文だけゴシックに残す理由がない。日記はほとんどが本文なので、この選択は「明朝を交えた組み方にする」という変更そのものを空振りにする。

### 決定2：エントリ本文の体裁は `.prose` として base.css に置く

公開サイトの日別ページは `.body`、編集アプリケーションのプレビューは `.preview-body` という別々の class を持ち、どちらも書体を持たずに `body` から受け継いでいる。書体が1つだったあいだは、これで字面が一致していた。

明朝を当てる先ができると、この形は保てない。両方に書けば写しが2つになり、片方だけ直したときにプレビューと公開後がずれる。`visual-identity` の「プレビューと公開後の一致」は、それを禁じている。

そこで `src/styles/base.css` に `.prose` を置き、両方の要素に class として足す。名前はあちらと同じ `.prose` にする。既存の `.body` / `.preview-body` は配置のための class として残し、字面だけを `.prose` が持つ。

**中身は書体と字送りだけ**にする。

```
font-family: var(--font-serif);
font-weight: 500;
font-size: 1.05rem;
line-height: 2.05;
letter-spacing: 0.04em;
```

大きさを 1rem から 1.05rem へ上げるのは、明朝が同じ級数でもゴシックより小さく見えるためで、あちらが `.prose` に同じことをしている。あちらの `.prose` が持つ `display: grid; gap: 1.6rem` は写さない。あれは段落を自分で並べるための指定で、日記の本文は Markdown から起こした `<p>` の余白で組まれている。

**代替案：`base.css` に `.body, .preview-body { ... }` と書く。** 採らない。共有の CSS がページ固有の class 名を知ることになり、画面を足すたびに選択子が伸びる。

**404 の文にも `.prose` を当てる。** 1rem の地の文が、サイトの中でここだけゴシックで残ることを避ける。

### 決定3：`--radius-sm` と `--accent-soft` を廃す

**`--radius-sm`（8px）は日記が作った唯一の寸法である。** 作った理由は「`--radius`（12px）をそのままボタンや入力欄に当てると、横に長い箱ほど丸みが目立ち、フォームだけが丸くなる」ことだった。角丸が 2px になれば、この理由そのものが消える。2px とさらに小さい何かを分ける意味はない。

廃した結果、角丸は `--radius` の1つだけになる。囲み・ボタン・入力欄・ピル・写真・フォーカス環がすべて同じ 2px になり、日記の側で決めた寸法が1つもない状態に戻る。

**`--accent-soft` はピルの塗りにしか使っていない。** 塗りをやめると使い道がなくなる。あちらも同じコミットでこの変数を削っている。使い道のない基準値を残すと、次に「ここだけ色を変えたい」と思ったときの逃げ道になる（前回 決定2 と同じ判断）。

**代替案：将来のために残す。** 採らない。必要になった時点で、あちらの同じ変数から写せばよい。

### 決定4：ピルの塗りをやめたあと、見分けは「囲みの有無」と「枠の色」で付ける

あちらの `.tags` は、塗りつぶしの丸いピルから細い枠だけの箱になった。日記の `.pill` も同じ体裁にする（枠 `--border`、角丸 `--radius`、アクセントの字、0.78rem、字送り 0.1em）。

問題は、日記のピルが**あちらにない仕事を持っている**ことである。日記のピルは状態を示す。公開／下書き、実行中／未実行、いま見ている年／その他。この見分けを、これまでは塗りの有無が担っていた。塗りをやめると、残るのは字の色（`--accent` と `--fg-muted`）だけになる。

この2色は**輝度でほとんど差がない**。実測で明 1.145、暗 1.120 である。色相と彩度は違うが、輝度が並ぶ以上、色を頼りにできない見え方では区別できない。塗りをやめた分をそのまま失うことになる。

そこで、`is-quiet` の定義を変える。

| | 枠 | 字 |
| --- | --- | --- |
| `.pill` | `--border` | `--accent` |
| `.pill.is-quiet` | `transparent` | `--fg-muted` |
| `.pill[aria-current]` | `--accent` | `--accent` |

- **淡い側は囲みを持たない側にする。** これまでは「地を持たない側」だった。塗りが消えた以上、淡さを示すものを枠の側へ移す。`border-color: transparent` にして枠そのものは残すので、並んだときの箱の大きさは変わらない。
- **いま見ている年は枠をアクセント色にする。** ここだけは字も文言も他と同じ（年の数字）で、見分けの手がかりが体裁しかない。あちらの `.link:hover` が「枠の色を変えて注目を示す」形を既に持っているので、それを借りる。当てる先は `aria-current` にする。既にこの属性が付いており（`editor/src/pages/index.astro`）、体裁と意味が同じものを指す。

これで、際立たせる側とそうでない側は「囲みがあるか」で分かれ、そのうち現在地だけが枠の色で立つ。どれも色相に頼らない。

**代替案：塗りを日記だけ残す。** 採らない。あちらが「塗りつぶしの丸いタグは印象が柔らかい」として外したものを日記だけ残せば、`visual-identity` が禁じる「日記だけの体裁」になる。この変更の目的そのものにも反する。

**代替案：字の色の差だけで済ませる。** 採らない。上の実測のとおり、輝度が並ぶ。

**押せるピルのホバーは足さない。** 枠のアクセント色は現在地に使うと決めたので、ホバーで同じ色にすると意味が重なる。ピルにホバーの手応えがないのは前からであり、この変更で悪くなるものではない。足すなら別の変更で、`.link:hover` との関係ごと決める。

### 決定5：ホバーの浮き上がりをやめ、フォーカス環を細くする

あちらは `.link:hover` から `transform: translateY(-2px)` を外し、枠の色だけを変える形にした。日記で浮き上がるのは `a.button:hover` の1箇所なので、そこを外す。`transition` からも `transform` を落とす。枠の色が変わる手応えは残る。

`a.button` に浮き上がりを与えていた元の理由は「箱のリンクだけは浮かせ、ボタンは押す位置が動くと狙いが外れるので浮かせない」だった。両方が浮かなくなるので、この使い分けごと消える。

フォーカス環は 2px から 1px、角丸は直値の 2px から `var(--radius)` に変える。値としては同じ 2px だが、出どころが基準に移る。1px でもアクセント色と地のコントラストは明 5.842 / 暗 6.424 で、文字でないものに求められる 3:1 を上回る。

### 決定6：節の題は明示的にゴシックへ戻す

`.section-title` は `h2` に当てている。`h2` が明朝になるので、放っておくとここも明朝になる。あちらの `.section__title` は同じ理由で `font-family: var(--font-sans)` を明示しており、字面も 600 / 0.75rem / 字送り 0.24em に変わった。日記も同じ値を写す。

日本語には大文字化が効かないため、あちらの `text-transform: uppercase` は写さない。代わりに罫線を右へ伸ばす扱いはそのまま残す。`visual-identity` が「同じ見出しであることが分かる別の目印を用いてよい」として認めている形である。

編集アプリケーションでは、この class が記事編集画面の `label`（「本文（Markdown）」）にも当たる。`label` は縦積みなので当てた側で横並びに戻しているが、その扱いは変えない。

### 決定7：コントラストは塗りをやめたことで上がる。測るが、書き残さない

塗りをやめると、ピルの字は囲みの地ではなく紙の地の上に載る。実測は次のとおり。

| 組み合わせ | 変更前 | 変更後 |
| --- | --- | --- |
| ピルの字（明） | 4.64 | 5.842 |
| ピルの字（暗） | 4.86 | 6.424 |
| `is-quiet` の字（明） | 5.103 | 5.103 |
| `is-quiet` の字（暗） | 7.194 | 7.194 |

前回いちばん低かったピル（明 4.64）が上がり、日記に実在する組み合わせの最低値は `is-quiet` の 5.103（明）になる。本文は 16.084（明）/ 12.705（暗）で変わらない。色を触らないので、罫線の淡さ（明 1.164 / 暗 1.670）も前回のままである。

**測った数値は `tokens.css` にも `base.css` にも書かない**（前回 決定4 と同じ）。出どころがあちらである以上、日記に数値の根拠を持たせると出どころが2つになる。記録はこの design と tasks に置く。

## Risks / Trade-offs

- **明朝の載っていない環境では総称 `serif` に落ちる** → Linux の一部や、Noto Serif JP を持たない Android がこれにあたる。あちらとまったく同じ落ち方であり、日記だけの問題ではない。Web フォントを読み込まないのは前々回から続く判断で、ここで覆さない。
- **`palt` を持たない書体では効かない** → 約物が詰まらないだけで、読めなくなるものはない。
- **プレビューと公開後がずれる** → 決定2 で `.prose` を1つにするが、**class を付け忘れれば同じことが起きる。** 実装後、両方の HTML に `prose` が出ていることを確認する。
- **本文が 1rem から 1.05rem になり、行の折り返しが変わる** → 1119 件すべての本文で起きる。字数を数えて組んだ行はないので内容には影響しないが、旧サイトから引き継いだ記事が本文に直接書いている `table`（画像の横並び）は幅の計算に関わる。`table-layout: fixed` で列幅は等分されるため、字の大きさでは崩れない。念のため、写真を並べた記事を実際に開いて確かめる。
- **ピルが目立たなくなる** → 決定4 で見分けは付け直したが、**紙の地の上に細い枠が1本という見え方そのものは、塗りつぶしより静かである。** これはあちらが意図した変化（「印象が柔らかいので、細い枠だけにして字送りで見せる」）であり、受け入れる。公開サイトの年・月の並びは、この静けさがいちばん大きく出る場所になる。
- **`--radius-sm` を廃すと、8px を当てていた8つの宣言（6種類）が 2px になる** → ボタン・入力欄・ファイル選択のボタン・`pre`・写真の縮小画像・置き換え待ちの枠。うしろの2つは記事の編集画面と写真の一覧に1つずつある。写真の縮小画像だけは、角丸が写真そのものに掛かる。2px はほぼ直角なので、丸め残りが目立つことはない。
- **公開ボタンとの競合** → 前々回・前回と同じ形の危険がある。編集アプリケーションの「公開」は GitHub の `main` を作り直して配るため、このブランチが `main` に入る前に手元から production へ配ると、ボタンが押された時点で公開サイトだけが旧い組み方に戻る。下の Migration Plan で扱う。

## Migration Plan

前回は design が定めた順（staging → マージ → production）を実際には守らず、マージを後に回した。同じ窓を三度開けない。

1. staging へ配って確認する。ここは `main` と結び付いていないので、いつ配ってもよい。
2. **`main` にマージする。**
3. その後に production へ配る。マージ済みなら、「公開」ボタンが押されても配られるのは新しい組み方である。

**切り戻し**：触れるのは CSS と、`.prose` の class を足すマークアップだけである。ファイルを戻して配り直せば元に戻る。データにも URL にも影響がなく、生成されるページの集合も変わらない。
