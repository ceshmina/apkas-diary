## Why

日記の追加・修正は現在 CLI からしか行えない。Markdown ファイルを手元に用意し、リポジトリを clone した端末で `npm run entry` を叩き、AWS の SSO セッションが生きている必要がある。日記は毎日書くものであり、手元の開発環境が整っていない状況（別の端末、外出先）で書けないことが、書く頻度そのものを下げている。

ブラウザから本文を書いて保存できるようにする。認証は Google ログインとし、パスワードを新たに作らず、AWS の認証情報を端末に置かずに済む状態にする。

## What Changes

- **編集アプリケーションを新設する。** ブラウザ上でエントリの一覧・作成・編集・下書き/公開の切り替えを行う。データストアは既存の DynamoDB テーブルをそのまま使い、CLI と同じエントリを読み書きする。
- **Google アカウントによる認証を導入する。** OAuth 2.0 / OIDC の Authorization Code フローを用い、許可された1アカウントのみを通す。OAuth クライアントは既存の Google Cloud プロジェクト `apkas-staging` / `apkas-production` に環境ごとに作る。
- **実行基盤はリクエスト駆動にする。** 常時稼働するサーバーを置かず、リクエストが来たときだけ実行され、終われば何も残らない構成にする。アイドル時の課金が発生しないことを要求として持つ。初回アクセスのコールドスタートによる待ちは許容する。
- **編集アプリケーションは独自のサブドメインで配信する。** 公開サイト（`diary.*`）・写真（`photos.*`）と並ぶ第3の配信先として `admin.*` を追加する。
- **`deployment-environments` にコード管理の例外を1つ追加する。** Google Cloud 側の OAuth クライアントは Terraform の管理下に置かず、手順を文書化したうえで手で用意する対象とする。

### Non-goals

- **公開サイトのビルドとデプロイは対象外。** 編集アプリケーションの責務は DynamoDB への書き込みまでとする。静的サイトへの反映は従来どおり手元の `npm run build` / `npm run deploy` で行う。編集内容が公開サイトに現れるタイミングは変わらない。
- **写真の投入は対象外。** 従来どおり `npm run photo` で手元から行う。
- **複数利用者への開放は対象外。** 利用者は本人1名であり、権限の段階や共有の仕組みは持たない。

## Capabilities

### New Capabilities

- `entry-editing`: ブラウザからエントリを一覧・作成・編集し、下書きと公開を切り替える振る舞い。CLI と同一のデータを扱い、両者の間で不整合が生じないこと。
- `editor-access-control`: 編集アプリケーションへの到達を、Google アカウントで本人であると確認できた場合のみに限ること。未認証の要求がデータに一切届かないこと。
- `editor-hosting`: 編集アプリケーションの配信と実行。独自ドメインでの HTTPS 配信、使われていない間に費用が発生しないこと、環境ごとの独立。

### Modified Capabilities

- `deployment-environments`: 「すべてのリソースはコードで管理される」の例外に、Google Cloud 側の OAuth クライアントを追加する。あわせて、環境の選択が AWS の named profile だけでなく、環境ごとに分かれた Google Cloud プロジェクトとも対応することを要求に含める。

## Impact

- **新規のアプリケーションコード。** 編集アプリケーションを収める新しいディレクトリ。既存の `src/lib`（日付ユーティリティ、DynamoDB アクセス、写真の URL 規約）を共有し、エントリの読み書きのロジックを二重に持たない。
- **新規の Terraform モジュール。** 編集アプリケーションの実行基盤・配信・DNS・証明書、およびアプリケーションが読む設定値の置き場所。`terraform/envs/staging` と `terraform/envs/production` の双方から呼ぶ。
- **DynamoDB テーブルへの書き込み経路が増える。** これまで書き手は手元の CLI だけだった。編集アプリケーションの実行ロールに、当該テーブルへの最小限の権限を与える。
- **Google Cloud への依存が生じる。** 認証の可用性が Google に依存する。編集ができないあいだも CLI からの登録は従来どおり動くため、日記が書けなくなる事態にはならない。
- **環境設定とドキュメント。** `config/<環境>.env` に編集アプリケーション向けの項目が増える。README に初期セットアップ（OAuth クライアントの作成、許可アカウントの登録）と日々の運用の手順を追加する。
