## Why

日記本文が参照する写真のうち **2,365件**（production、全体の約99%）は旧基盤 `photos.old.apkas.net` に置かれたままで、新しい写真基盤（新 S3 + 目録）の管理外にある。目録（`photo-catalog`）に記録が無いため編集画面の写真一覧に現れず、撮影情報も残っていない。旧基盤は管理されないホストであり、そこに日記の写真の実体があり続けること自体がリスクである。

調査の結果、旧ホストの `/original/` 配下に **EXIF が完全に残った元写真**（Lightroom 書き出しの JPEG、3840px）がいまも取得可能であることを確認した。配信用 WebP は EXIF が除去済みなので、元写真が取れる今のうちに移行すれば、新規投入と完全に同等の記録（撮影情報込み）を遡って作れる。旧 S3 へは AWS SSO（`apkas` プロファイル）で直接アクセスできることも確認済み。

また、これとは別に、目録機能の導入以前に新基盤へ投入された写真には目録の記録が無い（README にも「過去に投入した写真は目録に無い」と明記されている）。元写真は upload バケットに残っているため、こちらは再処理を発火させるだけで解消できる。

## What Changes

- **移行 CLI を追加する**（`src/cli/` 配下、`import-legacy` と同じ流儀）。次の段階からなる。
  - **棚卸し**: DynamoDB の全エントリ本文から旧 URL を抽出し、旧 URL → 新 sourceKey → 新 URL の対応表（manifest）を生成する。衝突・パターン逸脱を検出し、dry-run で全件を検証してから先へ進む。
  - **取り込み**: 旧 S3 から元写真を取得し、upload バケットへ日付規約（`YYYY/MM/DD/<ファイル名>`）で投入する。派生画像の生成と目録への記録は既存の photo-resize Lambda がそのまま行う。**移行スクリプトは DynamoDB の目録を直接書かない。** 元写真が取得できない場合のみ、配信用の `/large/` WebP（3840px、EXIF 無し）へフォールバックし、その旨を manifest に記録する。
  - **検証**: manifest 全行について、新しい配信 URL の疎通と目録の記録の存在を照合する。
  - **本文の書き換え**: 検証が通ったあと、エントリ本文中の旧 URL（Markdown `![]()` 約1,871件・raw HTML `<img src>` 約494件）を新 URL に置換し、既存の `putEntry()` 経由で書き戻す。
- **目録未登録の新基盤写真を再処理する**: upload バケットと目録の差分を取り、欠けている元写真を S3 の自己コピーで再処理させ、目録の記録（EXIF 込み）を埋める。
- **README を更新する**: 「過去に投入した写真は目録に無い」の記述を、移行後の状態に合わせて改める。
- 全工程を staging（旧参照59件）でリハーサルしてから production に適用する。

### スコープ外

- **旧ホスト（`photos.old.apkas.net`）の廃止**。本文からの参照は無くなるが、DNS・配信の停止は別の change で扱う。
- **表示側の変更**。本文の URL が変わるだけで、公開サイト・編集画面の表示ロジックには手を入れない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

なし。この change はデータの移行と一回性の tooling であり、システムの振る舞いの要求は変わらない。写真の目録への記録は既存の `photo-catalog` / `photo-ingest` の仕組み（投入 → 変換 → 記録）をそのまま通すため、「目録へ書けるのは投入と変換だけ」という既存の要求にも抵触しない。`.openspec.yaml` に `skip_specs: true` を設定する。

## Impact

- **DynamoDB（production）**: 目録に約2,365件の記録が追加される。エントリ約720件の本文が書き換わる（旧 URL → 新 URL のみ、他は不変）。
- **S3**: upload バケットに元写真 約2,365件（約5〜10GB）、delivery バケットに派生4サイズが追加される。
- **コード**: `src/cli/` に移行スクリプトを追加。既存の表示・投入コードは変更しない。
- **README**: 目録の適用範囲の記述を更新。
- **旧基盤**: 読み取りのみ。旧 S3・旧ホストには一切書き込まない。
