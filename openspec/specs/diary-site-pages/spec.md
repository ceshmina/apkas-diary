# diary-site-pages Specification

## Purpose
公開サイトの訪問者が日記に辿り着くための入口と経路を定める。日記を読む体験は「最近を読む」「特定の日を読む」「過去を遡る」の3種類に分かれ、それぞれに対応するページを用意する。
## Requirements
### Requirement: サイトは静的に生成され、閲覧に認証を要さない

すべてのページは事前に生成された静的なページとして配信されなければならない（MUST）。閲覧にログインや認証を要求してはならない（MUST NOT）。

#### Scenario: 認証なしでの閲覧

- **WHEN** 訪問者が任意の公開ページにアクセスする
- **THEN** 認証を求められることなくページが表示される

#### Scenario: 下書きは配信物に含まれない

- **WHEN** 下書き状態のエントリが存在する状態でサイトを生成する
- **THEN** そのエントリの本文はいかなる生成物にも含まれない

### Requirement: トップページは最新のエントリを表示する

サイトのルートは、公開済みエントリを新しい順に一定件数表示しなければならない（MUST）。

#### Scenario: トップページの表示

- **WHEN** 訪問者がサイトのルートにアクセスする
- **THEN** 公開済みエントリが日付の新しい順に表示され、各エントリから日別ページへ辿れる

#### Scenario: エントリが1件もない場合

- **WHEN** 公開済みエントリが存在しない状態でトップページにアクセスする
- **THEN** エラーにならず、エントリがない旨が表示される

### Requirement: 日別ページで個々のエントリを読める

各エントリは `/<年>/<月>/<日>` の形式のパスで読めなければならない（MUST）。月と日は2桁のゼロ埋めとする。

#### Scenario: 公開エントリの日別ページ

- **WHEN** 訪問者が公開済みエントリの日付のパス（例 `/2026/08/01`）にアクセスする
- **THEN** そのエントリのタイトルと本文が、Markdown を整形した形で表示される

#### Scenario: エントリのない日付

- **WHEN** 訪問者がエントリの存在しない日付のパスにアクセスする
- **THEN** 404 が返る

#### Scenario: 下書きの日付

- **WHEN** 訪問者が下書き状態のエントリしかない日付のパスにアクセスする
- **THEN** 404 が返り、下書きの存在は判別できない

### Requirement: 年別・月別のアーカイブページを提供する

エントリが存在する年について `/<年>`、エントリが存在する年月について `/<年>/<月>` のアーカイブページを提供しなければならない（MUST）。

#### Scenario: 年別アーカイブ

- **WHEN** 訪問者が `/2026` にアクセスする
- **THEN** その年の公開済みエントリの一覧が日付順で表示され、各エントリから日別ページへ辿れる

#### Scenario: 月別アーカイブ

- **WHEN** 訪問者が `/2026/08` にアクセスする
- **THEN** その月の公開済みエントリの一覧が日付順で表示される

#### Scenario: エントリのない年月

- **WHEN** 訪問者がエントリの存在しない年または年月のパスにアクセスする
- **THEN** 404 が返る

### Requirement: 「N年前の今日」を月日単位で辿れる

暦上の月日を指定して、過去のすべての年の同じ月日のエントリを一覧できなければならない（MUST）。静的サイトでは閲覧時刻を生成時に確定できないため、月日ごとのページをあらかじめ用意する。

#### Scenario: 月日ページの網羅

- **WHEN** サイトを生成する
- **THEN** 2月29日を含む366通りすべての月日についてページが生成される

#### Scenario: 過去の同じ月日のエントリ一覧

- **WHEN** 訪問者が月日を指定したパス（例 `/on-this-day/08-01`）にアクセスする
- **THEN** 年をまたいだすべての 8月1日 の公開済みエントリが年の降順で表示される

#### Scenario: 該当するエントリがない月日

- **WHEN** 訪問者がどの年にもエントリのない月日のページにアクセスする
- **THEN** 404 ではなくページが表示され、該当するエントリがない旨が示される

#### Scenario: 訪問した日の分に辿り着ける

- **WHEN** 訪問者がサイト上の「今日の分」への導線をたどる
- **THEN** 生成時刻ではなく訪問時刻の月日に対応するページに到達する

### Requirement: 本文は Markdown として整形して表示する

エントリ本文は Markdown として解釈し、整形された形で表示しなければならない（MUST）。

#### Scenario: Markdown の整形

- **WHEN** 見出し・箇条書き・リンクを含む本文を持つエントリの日別ページを表示する
- **THEN** それぞれが対応する要素として整形されて表示される
