# photo-ingest Specification

## Purpose
元写真を受け取り、公開してよい形の派生画像に変換するまでの経路を定める。撮影者の居場所や機材といった、写真を見せることに必要のない情報が公開物に混じらないことと、変換の元になった写真が失われないことを担保する。
## Requirements
### Requirement: 元写真の投入が派生画像の生成を起こす

元写真がアップロード先に置かれたとき、派生画像の生成は人の操作を要さずに始まらなければならない（MUST）。生成された派生画像は配信先に置かれなければならない（MUST）。

生成は投入と同期しない。投入の完了は、派生画像がまだ配信可能になっていないことを含みうる。

#### Scenario: 元写真の投入

- **WHEN** 元写真をアップロード先に置く
- **THEN** 生成を指示する操作をしないまま、しばらく後に派生画像が配信先に現れる

#### Scenario: 投入直後の参照

- **WHEN** 投入した直後に配信先の URL を要求する
- **THEN** まだ生成が終わっていなければ画像は返らない。生成が終わったあとの要求では返る

### Requirement: 派生画像は定められた4つのサイズで生成される

1枚の元写真から、長辺の長さが以下である4つの派生画像が生成されなければならない（MUST）。

| 名前 | 長辺 |
| --- | --- |
| `thumbnail` | 240px |
| `small` | 960px |
| `medium` | 1920px |
| `large` | 3840px |

縦横比は元写真のものが保たれなければならない（MUST）。切り抜きを行ってはならない（MUST NOT）。

元写真の長辺が指定より短い場合、拡大してはならない（MUST NOT）。そのサイズの派生画像は元写真と同じ大きさで生成されなければならない（MUST）。生成をとりやめてはならない（MUST NOT）。4つの派生画像は、元写真の大きさによらず常に揃って存在する。

#### Scenario: 十分に大きい元写真

- **WHEN** 長辺 4000px・横長の写真を投入する
- **THEN** 長辺がそれぞれ 240px / 960px / 1920px / 3840px の4つが生成され、いずれも元写真と同じ縦横比を持つ

#### Scenario: 縦位置の写真

- **WHEN** 長辺が高さ側にある写真を投入する
- **THEN** 指定の長さは高さに適用され、幅は縦横比から決まる

#### Scenario: 小さい元写真

- **WHEN** 長辺 1000px の写真を投入する
- **THEN** `thumbnail` は 240px、`small` は 960px、`medium` と `large` はいずれも元写真と同じ 1000px になる

#### Scenario: 指定より小さいサイズの欠落がない

- **WHEN** 元写真より大きいサイズの派生画像を要求する
- **THEN** 元写真と同じ大きさの画像が返る。存在しないという応答にはならない

### Requirement: 派生画像は WebP で生成される

すべての派生画像は WebP でなければならない（MUST）。元写真の形式によって出力の形式が変わってはならない（MUST NOT）。

#### Scenario: JPEG の投入

- **WHEN** JPEG の写真を投入する
- **THEN** 生成された4つはいずれも WebP である

#### Scenario: PNG の投入

- **WHEN** PNG の画像を投入する
- **THEN** 生成された4つはいずれも WebP である

### Requirement: 派生画像から撮影に関する情報がすべて除去される

派生画像には、EXIF・IPTC・XMP のいずれの形式であっても、元写真に含まれていた付随情報が残ってはならない（MUST NOT）。GPS による撮影場所、撮影日時、機材、撮影者名のいずれも、配信されるファイルから読み取れてはならない（MUST NOT）。

#### Scenario: 位置情報を持つ写真

- **WHEN** GPS 情報を含む写真を投入し、生成された派生画像の付随情報を読み出す
- **THEN** 座標はいっさい含まれていない

#### Scenario: 撮影日時と機材

- **WHEN** 撮影日時と機材名を含む写真を投入し、生成された派生画像の付随情報を読み出す
- **THEN** 撮影日時も機材名も含まれていない

#### Scenario: 付随情報の全般

- **WHEN** 生成された派生画像の付随情報を読み出す
- **THEN** 元写真に由来する項目がひとつも見つからない

### Requirement: 付随情報の除去によって見え方が変わらない

付随情報の除去は、写真の見え方を変えてはならない（MUST NOT）。除去によって失われる情報のうち表示に影響するものは、除去の前に画素そのものへ反映されなければならない（MUST）。

具体的には、**向き**と**色**が対象になる。付随情報に記録された回転を単に捨てると縦位置の写真が横倒しになり、色空間の記述を単に捨てると、標準色空間の外で撮られた写真の色が変わる。

#### Scenario: 回転情報を持つ写真

- **WHEN** 付随情報に回転が記録された縦位置の写真を投入する
- **THEN** 派生画像は縦位置のまま表示される。付随情報を持たないビューアで開いても向きは正しい

#### Scenario: 標準色空間の外で撮られた写真

- **WHEN** 標準色空間より広い色空間で記録された写真を投入する
- **THEN** 派生画像の見た目の色は元写真と同じである

### Requirement: 元写真は保管され、公開されない

元写真は派生画像の生成後も削除されてはならない（MUST NOT）。元写真は配信経路から取得できてはならない（MUST NOT）。

元写真を保つのは、生成するサイズを足すとき、品質の設定を変えるとき、将来ほかの形式へ移るときに、手元からの再投入なしに作り直せるようにするためである。

#### Scenario: 生成後の元写真

- **WHEN** 派生画像の生成が完了したあとにアップロード先を確認する
- **THEN** 元写真がそのまま残っている

#### Scenario: 元写真への到達

- **WHEN** 配信経路から元写真を取得しようと試みる
- **THEN** 取得できない

#### Scenario: 元写真の取り違えからの復旧

- **WHEN** 元写真を誤って上書きする
- **THEN** 上書き前の元写真を取り戻せる

### Requirement: 同じキーへの再投入は派生画像を作り直す

すでに投入したことのあるキーに元写真を投入したとき、そのキーに対応する4つの派生画像は新しい元写真から作り直されなければならない（MUST）。古い派生画像が残ってはならない（MUST NOT）。

#### Scenario: 内容の差し替え

- **WHEN** すでに派生画像のあるキーに、別の内容の元写真を投入する
- **THEN** 4つの派生画像はいずれも新しい内容から作り直される

#### Scenario: 同じ内容の再投入

- **WHEN** 同じ内容の元写真を同じキーに投入し直す
- **THEN** 派生画像の内容は変わらない

### Requirement: 画像として読めないものからは派生画像を作らない

投入されたファイルを画像として読めない場合、配信先にオブジェクトを置いてはならない（MUST NOT）。失敗は後から確認できる形で記録されなければならない（MUST）。

読めなかったことによって、以後の投入の処理が止まってはならない（MUST NOT）。

#### Scenario: 画像でないファイルの投入

- **WHEN** 画像でないファイルをアップロード先に置く
- **THEN** 配信先には何も置かれず、失敗が記録に残る

#### Scenario: 失敗のあとの投入

- **WHEN** 失敗の直後に正常な写真を投入する
- **THEN** その写真の派生画像は通常どおり生成される

### Requirement: 写真の投入は対象環境を明示して行う

写真を投入する操作は、対象の環境が明示されないまま実行できてはならない（MUST）。一方の環境への投入が、他方の環境の配信内容を変えてはならない（MUST NOT）。

#### Scenario: 環境の未指定

- **WHEN** 環境を指定せずに投入の操作を実行する
- **THEN** 何も投入されないまま失敗する

#### Scenario: 環境の分離

- **WHEN** staging に写真を投入する
- **THEN** production の配信にはその写真が現れない

### Requirement: 投入の結果として得られる URL が分かる

投入の操作は、その写真が配信される URL を操作者に示さなければならない（MUST）。操作者が URL の組み立て規約を覚えている必要があってはならない（MUST NOT）。

#### Scenario: 投入の完了

- **WHEN** 写真の投入が成功する
- **THEN** その写真の配信 URL が表示され、本文にそのまま書ける

### Requirement: 元写真はブラウザからも投入できる

編集アプリケーションは、ブラウザから元写真を投入する手段を提供しなければならない（MUST）。投入された元写真は、手元の CLI から投入した場合と同じアップロード先に置かれなければならない（MUST）。

投入の経路によって、派生画像の生成・サイズ・形式・付随情報の除去が変わってはならない（MUST NOT）。どちらの経路から投入されたかを、生成された派生画像から判別できてはならない（MUST NOT）。

編集アプリケーションが1つの要求として受け取れる大きさによって、投入できる元写真の大きさが制限されてはならない（MUST NOT）。日記に載せる写真は、日記の本文よりはるかに大きい。文章を書くための入口が受け取れる大きさに、写真が縛られる理由がない。

#### Scenario: ブラウザからの投入

- **WHEN** 編集アプリケーションから元写真を投入する
- **THEN** 生成を指示する操作をしないまま、しばらく後に派生画像が配信先に現れる

#### Scenario: 経路によらない生成

- **WHEN** 同じ元写真を、同じキーになるように CLI とブラウザからそれぞれ投入する
- **THEN** 生成される4つの派生画像は同じものになる

#### Scenario: 大きい元写真

- **WHEN** 数十 MB の元写真をブラウザから投入する
- **THEN** 投入は成立し、派生画像が生成される

### Requirement: 複数の元写真をまとめて投入できる

編集アプリケーションは、複数の元写真を一度の操作で投入できなければならない（MUST）。1枚ずつ選び直すことを要求してはならない（MUST NOT）。

まとめて投入された元写真は、**それぞれ独立に**扱われなければならない（MUST）。1枚の失敗が他の枚の投入を取り消してはならない（MUST NOT）。何枚目まで済んだかが利用者に分かる形でなければならない（MUST）。

日記に載せる写真は1日に数枚ある。1枚ごとに画面を往復すると、枚数だけ手数が増える。

#### Scenario: 複数枚の選択

- **WHEN** 複数の元写真を選んで投入する
- **THEN** すべてが投入され、それぞれの配信 URL が示される

#### Scenario: 一部が失敗する

- **WHEN** 複数枚のうち1枚が投入に失敗する
- **THEN** 残りの投入は成立し、どれが失敗したかが分かる

#### Scenario: 投入の進み

- **WHEN** 複数枚の投入に時間がかかっている
- **THEN** 何枚のうち何枚が済んだかが分かる

### Requirement: ブラウザからの投入先は編集アプリケーションが決める

ブラウザからの投入において、元写真が置かれるキーは編集アプリケーションが決めなければならない（MUST）。利用者が任意のキーを指定できてはならない（MUST NOT）。

キーは投入時に指定された日付とファイル名から決まり、CLI が同じ日付と同じファイル名に対して作るものと一致しなければならない（MUST）。

同じ規則にするのは、投入の経路が2つになっても写真の置き場所が1つの規則で決まるようにするためである。経路ごとに違う場所へ置くと、あとから「どちらで入れたか」を思い出さないと写真に辿り着けなくなる。

#### Scenario: 日付を指定した投入

- **WHEN** 日付 `2026-08-11` を指定して `IMG_1234.jpg` をブラウザから投入する
- **THEN** 元写真は CLI が `--date 2026-08-11 --file IMG_1234.jpg` に対して作るのと同じキーに置かれる

#### Scenario: 指定した日付の外への投入

- **WHEN** 投入を許された日付の外へ元写真を置こうと試みる
- **THEN** 拒否され、アップロード先には何も置かれない

#### Scenario: キーを直接指定する手段

- **WHEN** ブラウザからの投入で操作しうるすべてを確認する
- **THEN** キーを直接指定する手段は存在しない

### Requirement: ブラウザからの投入を許す資格は対象と期間が限られる

元写真をアップロード先へ直接置くために発行される資格は、本人であることが確認できていない要求に対して発行してはならない（MUST NOT）。

発行された資格は、置ける対象が指定された日付の下に限られなければならない（MUST）。有効期間を持たなければならない（MUST）。期限を過ぎた資格による書き込みを受け付けてはならない（MUST NOT）。

この資格は、書き込み以外のことをできてはならない（MUST NOT）。既にアップロード先にある元写真の読み出し、一覧、削除のいずれもできてはならない（MUST NOT）。

#### Scenario: 未認証での取得

- **WHEN** 認証されていない者が投入の画面へ要求を送る
- **THEN** 資格は発行されず、アップロード先へ書き込む手段は得られない

#### Scenario: 期限切れの資格

- **WHEN** 発行から十分な時間が経った資格で元写真を置こうと試みる
- **THEN** 拒否され、アップロード先には何も置かれない

#### Scenario: 資格でできること

- **WHEN** 発行された資格を用いて、書き込み以外の操作をアップロード先に対して試みる
- **THEN** いずれも拒否される

### Requirement: ブラウザからの投入では生成の完了が示される

ブラウザから投入した利用者に対して、その写真の派生画像が配信可能になったかどうかが示されなければならない（MUST）。まだ生成が終わっていない状態を、終わったものとして示してはならない（MUST NOT）。

すでに派生画像のあるキーへ投入し直した場合、**前回の派生画像が残っていること**をもって終わったと示してはならない（MUST NOT）。差し替えのときこそ、古い内容を指す URL を本文に書いてしまわないよう待つ意味がある。

完了を確かめる操作が、その後の配信を妨げてはならない（MUST NOT）。

#### Scenario: 投入の直後

- **WHEN** 投入を終えた直後に画面を見る
- **THEN** まだ生成が終わっていないことが示される

#### Scenario: 生成の完了

- **WHEN** 生成が終わったあとに画面を見る
- **THEN** 終わったことが示され、示された URL を開くと画像が返る

#### Scenario: 複数枚の完了

- **WHEN** 複数枚を投入し、一部だけ生成が終わっている
- **THEN** どの写真が開ける状態でどれがまだかが、枚ごとに分かる

#### Scenario: 差し替えの完了

- **WHEN** すでに派生画像のあるキーへ別の内容の元写真を投入する
- **THEN** 新しい派生画像が出来るまでは終わったと示されず、出来てから終わったと示される

#### Scenario: 確認による配信への影響

- **WHEN** 完了を繰り返し確かめたのちに、示された URL を開く
- **THEN** 確かめなかった場合と同じように画像が返る
